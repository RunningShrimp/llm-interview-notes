# 01 · 哈希：用空间换时间的第一课

> 热题 100 · 哈希组 · 3 题。哈希表的一句话卖点：把"某个东西存不存在 / 在哪"的查询从 O(n) 干到 O(1)。这一组题的共同主线是——**拿什么当 key**。key 想清楚了，代码都是顺手的事。

## LC1 两数之和（简单）

### 题干简述

LeetCode 1 · Two Sum · 简单。给定整数数组 `nums` 和目标值 `target`，找出数组中**和为 target** 的两个整数，返回它们的**下标**。答案恰好存在一个，同一元素不能重复使用。

示例：`nums = [2,7,11,15], target = 9` → 输出 `[0,1]`。

### 解题思路：为什么会想到哈希

先承认暴力很好想：两层循环枚举所有数对，O(n²)。但面试官下一句必然是："能 O(n) 吗？"

换个视角就通了。站在数字 `x` 的位置，我真正关心的只有一件事——**`target - x` 之前出现过吗？** 这是一个纯粹的"查存在性"问题，而哈希表就是为这个生的：O(1) 查询。

于是流程变成一次遍历：走到下标 `i`，先问 map 里有没有 `target - nums[i]`；有，直接出答案；没有，把 `nums[i] → i` 存起来，留给后面的数来查。

```
nums = [2, 7, 11, 15], target = 9

i=0 值 2：查 9-2=7，map 里没有 → 存 {2:0}
i=1 值 7：查 9-7=2，命中 map[2]=0 → 返回 [0,1]

map 演变：{} → {2:0}（第二个数查完直接返回，都没来得及存）
```

一个容易翻车的顺序问题：必须**先查后存**。如果先把 `nums[i]` 自己存进去再查，碰上 `target=8、nums[i]=4`，会查到自己，返回 `[i, i]`，直接挂。

### 代码

```go
package main

import "fmt"

func twoSum(nums []int, target int) []int {
	seen := make(map[int]int) // 值 -> 下标
	for i, v := range nums {
		if j, ok := seen[target-v]; ok { // 先查：配对数出现过吗
			return []int{j, i}
		}
		seen[v] = i // 后存：避免自己匹配自己
	}
	return nil
}

func main() {
	fmt.Println(twoSum([]int{2, 7, 11, 15}, 9)) // [0 1]
	fmt.Println(twoSum([]int{3, 2, 4}, 6))      // [1 2]
}
```

### 复杂度

| 解法 | 时间 | 空间 | 说明 |
|------|------|------|------|
| 暴力双层循环 | O(n²) | O(1) | 面试先说出来，再主动优化 |
| 哈希一次遍历 | O(n) | O(n) | 空间换时间的标准姿势 |

### 易错点

1. **先存后查**会自己匹配自己（`target=8, x=4` 时返回 `[i,i]`）——本题最经典的挂法。
2. 返回的是**下标**不是值；map 里 key 存值、value 存下标，别弄反。
3. 题目保证恰好一个答案，不用收集多解；如果面试官追问"没有这个保证呢"，才需要讨论。

### 🎤 口述模板

"暴力是两层循环 O(n²)；优化思路是空间换时间——遍历数组时，对每个数 x 查一下 target 减 x 是否在前面出现过，哈希表让这个查询变成 O(1)。注意先查再存，避免自己匹配自己。整体一次遍历，时间 O(n)，空间 O(n)。"

## LC49 字母异位词分组（中等）

### 题干简述

LeetCode 49 · Group Anagrams · 中等。给定字符串数组，把**字母异位词**（字母相同、顺序不同的词，如 eat/tea/ate）组合到一起。返回分组结果，组间顺序不限。

示例：`["eat","tea","tan","ate","nat","bat"]` → `[["eat","tea","ate"],["tan","nat"],["bat"]]`。

### 解题思路：核心是设计 key

所有"分组"问题的通用套路：**找一个标准化 key——同组的元素算出来的 key 必须相同，不同组必须不同**，然后 `map[key][]string` 收集就完事了。

这道题的考点只剩：异位词的 key 怎么设计？两条路线：

```
路线一：排序串做 key（每个词的字母排序后当 key）

  "eat" ──字母排序──▶ "aet" ─┐
  "tea" ──字母排序──▶ "aet" ─┼──▶ map["aet"] = [eat tea ate]
  "ate" ──字母排序──▶ "aet" ─┘
  "tan" ──字母排序──▶ "ant" ─┐──▶ map["ant"] = [tan nat]
  "nat" ──字母排序──▶ "ant" ─┘
  "bat" ──字母排序──▶ "abt" ────▶ map["abt"] = [bat]

路线二：计数做 key（26 个字母的出现次数，编码成一个"指纹"）

  "eat" ──数字母──▶ [a:1 e:1 t:1] ─┐
  "tea" ──数字母──▶ [a:1 e:1 t:1] ─┼──▶ 同一个指纹 → 同一组
  "ate" ──数字母──▶ [a:1 e:1 t:1] ─┘
```

排序法直观好写；计数法每个词只扫一遍 O(k)，但"计数怎么当 key"要费点心思——Java 里得拼字符串，而 **Go 的福利是 `[26]int` 数组属于可比较类型，能直接当 map 的 key**，还能直接 `==` 比较。面试里主动提这一点是个小加分。

### 解法一代码：排序串做 key

```go
package main

import (
	"fmt"
	"sort"
)

func groupAnagrams(strs []string) [][]string {
	groups := make(map[string][]string)
	for _, s := range strs {
		b := []byte(s)
		sort.Slice(b, func(i, j int) bool { return b[i] < b[j] }) // 字母排序
		key := string(b)                                          // eat/tea/ate -> "aet"
		groups[key] = append(groups[key], s)
	}
	res := make([][]string, 0, len(groups))
	for _, g := range groups {
		res = append(res, g)
	}
	return res
}

func main() {
	fmt.Println(groupAnagrams([]string{"eat", "tea", "tan", "ate", "nat", "bat"}))
	// [[eat tea ate] [tan nat] [bat]]（组间顺序不保证）
}
```

### 解法二代码：计数数组做 key

```go
package main

import "fmt"

func groupAnagramsCount(strs []string) [][]string {
	groups := make(map[[26]int][]string) // [26]int 可比较，直接当 key
	for _, s := range strs {
		var cnt [26]int
		for _, c := range s {
			cnt[c-'a']++ // 统计每个字母出现次数
		}
		groups[cnt] = append(groups[cnt], s)
	}
	res := make([][]string, 0, len(groups))
	for _, g := range groups {
		res = append(res, g)
	}
	return res
}

func main() {
	fmt.Println(groupAnagramsCount([]string{"eat", "tea", "tan", "ate", "nat", "bat"}))
}
```

### 解法对比表

| | 排序串做 key | 计数数组做 key |
|---|---|---|
| 单个词的预处理 | O(k log k) | O(k) |
| 整体时间 | O(n · k log k) | O(n · k) |
| 空间 | O(n · k) | O(n · k) + O(26) |
| 实现难度 | 直观，几行搞定 | 要知道数组能当 key |
| 适用场景 | 字符串短的默认写法 | 字符串很长时更快 |

（n 是词数，k 是单词平均长度。）字符串不长时两者无感差别，面试写排序法即可，计数法作为"我还能更快"的补充。

### 易错点

1. 排序后得到的是 `[]byte`，**slice 不可比较、不能当 map key**，必须 `string(b)` 转回去。
2. 计数法的前提是**纯小写字母**；有 Unicode 或大写就得退回排序法，或换 `map[rune]int` 自己编码成字符串。
3. 结果组间顺序不保证，LeetCode 不卡这个；组内顺序保持输入时的相对顺序（append 天然保证）。

### 🎤 口述模板

"分组问题的本质是设计标准化 key：同组词 key 相同、异组词 key 不同。最直观的是把每个词的字母排序后当 key；更快的是 26 长度的计数数组当 key——Go 里数组可直接比较、直接做 map key，这点可以主动提。所有词按 key 聚进 map 再输出即可。排序版 O(n·k log k)，计数版 O(n·k)。"

## LC128 最长连续序列（中等）

### 题干简述

LeetCode 128 · Longest Consecutive Sequence · 中等。给定未排序整数数组，找出**最长连续数字序列**的长度（数值上相邻差 1，不要求在数组中位置相邻）。要求算法时间复杂度 **O(n)**。

示例：`[100,4,200,1,3,2]` → `4`（最长连续序列是 1,2,3,4）。

### 解题思路：HashSet + 只从起点数

排序再扫一遍能做，但 O(n log n)，题目点名要 O(n)，逼你换思路。

把所有数扔进 HashSet（O(n)）。此时对任意数 x，"x+1 在吗？x+2 在吗？……"每次查询都是 O(1)，顺着数下去就能量出以 x 开头的序列长度。

但直接对每个数都这么数会重复劳动：序列 1,2,3,4 会被 1、2、3、4 各数一遍，最坏退化到 O(n²)。

关键剪枝：**只有当 x-1 不在集合里时，x 才是某段序列的起点，才开工往后数**。

```
set = {100, 4, 200, 1, 3, 2}

x=1  ：0 不在 set → 是起点 ✔ 从 1 数到 4，长度 4
x=2  ：1 在  set → 跳过 ✘（属于 1 开头的序列，会被顺带数到）
x=3  ：2 在  set → 跳过 ✘
x=4  ：3 在  set → 跳过 ✘
x=100：99 不在 → 起点，长度 1
x=200：199 不在 → 起点，长度 1
```

这样每段序列只被它的起点完整数一次。把"不重复"总结成三笔账：

| 哪里可能重复 | 怎么避免 |
|---|---|
| 重复数字（数组里有多个 1） | set 天然吸收，只留一个 |
| 同一段序列被多个数反复数 | x-1 存在就跳过，只认起点 |
| 数序列时来回扫 | 从起点严格 +1 往后，不回头 |

每个数字全程最多被碰两次（入 set 一次、被某个起点顺带数到一次），整体 O(n)。

### 代码

```go
package main

import "fmt"

func longestConsecutive(nums []int) int {
	set := make(map[int]bool, len(nums))
	for _, v := range nums {
		set[v] = true // 重复数字在 set 里只占一个坑
	}
	ans := 0
	for v := range set {
		if set[v-1] { // 剪枝：v 不是起点，跳过
			continue
		}
		length := 1        // v 是起点，开工往后数
		for set[v+length] { // 每步 O(1) 查询
			length++
		}
		if length > ans {
			ans = length
		}
	}
	return ans
}

func main() {
	fmt.Println(longestConsecutive([]int{100, 4, 200, 1, 3, 2}))          // 4
	fmt.Println(longestConsecutive([]int{0, 3, 7, 2, 5, 8, 4, 6, 0, 1})) // 9
}
```

### 复杂度

| 解法 | 时间 | 空间 |
|------|------|------|
| 排序后线性扫 | O(n log n) | O(1)（原地排序） |
| HashSet + 起点剪枝 | O(n) | O(n) |

外层 for 看似套内层 while 像 O(n²)，别慌——起点的内层 while 总步数 = 所有序列长度之和 ≤ n，均摊到每个数就是 O(1)。这是本题面试最常被追问的点。

### 易错点

1. 判断起点是查 `set[v-1]` **存在则跳过**，逻辑别写反（写成"存在才数"就全错了）。
2. 遍历集合（`for v := range set`）而不是原数组，天然规避重复值多算（虽然对正确性影响不大，从数组遍历配剪枝也是对的，但从 set 遍历更干净）。
3. 空数组返回 0，代码天然覆盖，但面试时口头提一句边界更稳。

### 🎤 口述模板

"要 O(n) 就不能排序。先把所有数放进 HashSet，然后只从'序列起点'开始数：x-1 不在集合里，x 才是起点，才往后数 x+1、x+2……这个剪枝保证每段序列只被完整数一次，每个数最多被访问两次，整体 O(n)。没有这个剪枝，每个数都会把所在序列重数一遍，最坏 O(n²)。"

## 本组小结

| 题号 | 哈希在这里干了什么 |
|---|---|
| LC1 | 查"配对数出现过吗"，O(1) |
| LC49 | 设计标准化 key，把同类聚到一起 |
| LC128 | 查"x+1 / x-1 存在吗"，支撑起点剪枝 |

一句话：遇到"查存在 / 找配对 / 分同类"，先想哈希；然后花 80% 的精力设计 key 和去重。
