# 子串：前缀和 × 滑动窗口 × 单调队列

> 这一组的 3 道题，正好是「子数组/子串问题」的三大主流武器：
> LC560 教你 **前缀和 + 哈希**，LC239 引入 **单调队列** 这个新数据结构，LC76 是滑动窗口的终极 Boss（困难）。
> 面试里"连续子数组/子串"这类字眼一出现，基本逃不出这三个套路。

## 本组题目总览

| # | 题号 | 题目 | 核心考点 | 难度 |
|---|------|------|----------|------|
| 1 | LC560 | 和为 K 的子数组 | 前缀和 + 哈希表 | 中等 |
| 2 | LC239 | 滑动窗口最大值 | 单调队列 | 中等 |
| 3 | LC76  | 最小覆盖子串 | 不定长窗口 + 欠账计数 | 困难 |

拿到题先过一遍这个"分诊台"：

```
定长窗口          → 直接滑，进来一个出去一个
求个数/最短可行    → 双指针不定长窗口（要满足单调性！）
和为 K 且有负数    → 前缀和 + 哈希（滑动窗口失效）
窗口内最值维护     → 单调队列
```

## 一、LC560 和为 K 的子数组（中等）

### 题干简述

- **LeetCode 560. 和为 K 的子数组**，难度：中等
- 给你一个整数数组 `nums` 和一个整数 `k`，请统计并返回该数组中「元素和恰好等于 `k` 的**连续**子数组」的个数。

```
示例 1：nums = [1,1,1], k = 2  → 输出 2（两个 [1,1]）
示例 2：nums = [1,2,3],  k = 3  → 输出 2（[1,2] 和 [3]）
```

注意：子数组必须连续，不是子序列（子序列可以跳着选，那是另一类 DP 题）。

### 解题思路：为什么这题不能用滑动窗口

**先看暴力**：枚举所有子数组的起点和终点，每个区间再求和——三层循环 O(n³)；
稍微优化一点：固定起点，向后累加，和随时更新——两层循环 O(n²)。

面试时 O(n²) 可以先说，但一定要接着说"我可以在 O(n) 内做出来"。

**为什么滑动窗口不行？（面试官必追问）**

滑动窗口成立的前提是**单调性**：
- 窗口和太大了 → 缩小左边，和一定变小；
- 窗口和太小了 → 扩大右边，和一定变大。

有了这个单调性，指针才敢"义无反顾"地单向移动。但这题数组**可能有负数**：

```
nums = [1, 2, -2, 3], k = 3

窗口 [1,2,-2,3] 和 = 4，比 k 大。该缩左边吗？
缩掉 1 → [2,-2,3] 和 = 3 ✓ 命中！
但如果数组是 [1, 2, -2, 4]：
缩掉 1 → [2,-2,4] 和 = 4，还是大；再缩 2 → [-2,4] 和 = 2，又小了……
正负交替时"大了缩、小了扩"的因果链直接断裂，指针不知道该往哪走。
```

一句话总结：**负数让"扩大必增、缩小必减"失效，滑动窗口失去单调性基础**。

**正解：前缀和 + 哈希表**

定义 `preSum[i]` = 前 `i` 个数之和（`preSum[0] = 0` 表示"什么都不选"的空前缀），
那么任意子数组 `(i, j]` 的和 = `preSum[j] - preSum[i]`。

```
nums    =  [3, 4, 7]
preSum  = [0, 3, 7, 14]      ← preSum[i] = 前 i 个数之和，preSum[0] = 0（空前缀）

子数组 (i, j] 的和 = preSum[j] - preSum[i]
比如 [4,7] = preSum[3] - preSum[1] = 14 - 3 = 11 ✓
```

我们要求子数组和等于 k，即：

```
preSum[j] - preSum[i] = k
        ↓ 移项
preSum[i] = preSum[j] - k
```

于是扫到位置 j 时，只需要问一句：**"我左边有多少个前缀和等于 preSum[j] - k？"**
用哈希表 `map[前缀和]出现次数` 边走边记，一问一答，整体 O(n)。

还有一个细节：哈希表要预置 `{0: 1}`——如果 `preSum[j]` 本身就等于 k，
说明从下标 0 开头到 j 的子数组就是答案，此时 `preSum[j] - k = 0`，
得靠这个"空前缀"把它接住。

### 代码

```go
package main

// LC560 和为 K 的子数组：前缀和 + 哈希表
func subarraySum(nums []int, k int) int {
	count := 0
	preSum := 0
	// 哈希表：前缀和的值 -> 出现次数
	// 初始化 {0:1}：代表"一个数都不选"的空前缀，
	// 用来接住 preSum[j] 本身就等于 k（即从下标 0 开头）的情况
	m := map[int]int{0: 1}
	for _, x := range nums {
		preSum += x // preSum = nums[0..i] 之和
		// 之前出现过几个 preSum-k，以 i 结尾的合法子数组就有几个
		count += m[preSum-k]
		// 注意顺序：先查再存！否则 k=0 时会把"自己减自己"算进去
		m[preSum]++
	}
	return count
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 一趟扫描，哈希表 O(1) 读写 |
| 空间 | O(n) | 哈希表最多存 n+1 个不同的前缀和 |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 暴力枚举区间 | O(n²) | O(1) | 面试保底方案，先说出来再优化 |
| 滑动窗口 | ❌ | ❌ | 有负数，单调性不成立，做不了 |
| 前缀和 + 哈希 | O(n) | O(n) | 最优解，本质是"两数之和"的前缀版 |

### 易错点

1. **忘了初始化 `{0: 1}`**：从下标 0 开头的子数组永远统计不到，部分用例过不了。
2. **先存再查**：k=0 时 `preSum-k` 等于当前 `preSum` 本身，会把自己算进去，正确顺序是**先查再存**。
3. **上来就想滑动窗口**：被"连续子数组"骗了，一定要先问"数组有没有负数"。
4. **哈希表存的是"次数"不是"是否存在"**：同一个前缀和出现多次，每一个都能和当前 j 配对一个答案。

> 🎤 **口述模板**
> 「这题要求连续子数组和等于 k 的个数。因为数组可能有负数，滑动窗口的单调性被破坏，所以不能用。我的做法是前缀和加哈希表：边扫边维护前缀和 preSum，子数组 (i, j] 的和等于 preSum[j] 减 preSum[i]，要让它等于 k，就是找前面有多少个前缀和等于 preSum 减 k。哈希表记录每个前缀和出现的次数，初始化放一个 {0:1} 接住从头开始的子数组。注意先查再存，避免 k 等于 0 时把自己算进去。时间空间都是 O(n)。」

## 二、LC239 滑动窗口最大值（中等）

### 题干简述

- **LeetCode 239. 滑动窗口最大值**，难度：中等
- 给你一个整数数组 `nums` 和大小为 `k` 的滑动窗口。窗口从最左侧移到最右侧，每次移动一格，
  返回**每个窗口位置的最大值**组成的数组。

```
示例：nums = [1,3,-1,-3,5,3,6,7], k = 3

窗口位置                最大值
─────────────────────  ──────
[1  3  -1] -3  5  3      3
 1 [3  -1  -3] 5  3      3
 1  3 [-1  -3  5] 3      5
 1  3  -1 [-3  5  3]     5
 1  3  -1  -3 [5  3  6]  6
 1  3  -1  -3  5 [3  6  7] 7

输出：[3,3,5,5,6,7]
```

### 解题思路：怎么"增量维护"最大值

**暴力的痛点**：每个窗口重新扫一遍找最大值，O(n·k)，k 接近 n 时退化为 O(n²)。

观察窗口移动的本质：**每次只进来一个数、出去一个数**，中间 k-2 个数原封不动。
那最大值能不能也"增量维护"，而不是每次重算？

试两条路：
- **普通变量**记最大值？出去的数恰好是最大值时，不知道"老二"是谁，只能重扫。❌
- **大顶堆**？进来 O(log k)，出去时如果堆顶过期就懒删除，O(n log n) 能过，但写起来绕。⚠️

正解是**单调队列**：一个双端队列，永远保持两个不变量——

1. **存下标**（不是值！这样才能判断谁过期了），下标随位置递增；
2. 队列里下标对应的**值从队头到队尾单调递减**，所以**队头永远是当前窗口的最大值**。

**入队 / 出队规则 ASCII 图**（队列格式：`下标(值)`）：

```
nums = [1, 3, -1, -3, 5, 3, 6, 7],  k = 3

i=0 入 1        队列: [0(1)]                      窗口未满
i=1 入 3        1 < 3，队尾的 1 被弹掉             窗口未满
                队列: [1(3)]
i=2 入 -1       -1 < 3，直接排在后面               窗口 [1,3,-1]  → 答案=队头 3 ✓
                队列: [1(3), 2(-1)]
i=3 入 -3       直接排在后面                       窗口 [3,-1,-3] → 答案=3 ✓
                队列: [1(3), 2(-1), 3(-3)]
i=4 入 5        队尾 -3,-1,3 全部 ≤ 5，挨个弹掉    窗口 [-1,-3,5] → 答案=5 ✓
                队列: [4(5)]
i=5 入 3        3 < 5，排后面                      窗口 [-3,5,3]  → 答案=5 ✓
                队列: [4(5), 5(3)]
i=6 入 6        3,5 全弹掉；此时队头下标 4 已过期   窗口 [5,3,6]   → 答案=6 ✓
                （4 ≤ i-k=3，先清过期再入队）
                队列: [6(6)]
i=7 入 7        6 弹掉                            窗口 [3,6,7]   → 答案=7 ✓
                队列: [7(7)]
```

弹队尾的"歪理"：**你比我小，还比我先进窗口（先过期），只要我在，你就永远当不上最大值——留着干嘛？**

为什么是 O(n)？每个下标最多入队一次、出队一次（要么被后来者从队尾弹掉，要么从队头过期滑出），
所以总操作次数是 2n 量级，均摊每步 O(1)。

### 代码

```go
package main

// LC239 滑动窗口最大值：单调（递减）队列，存下标
func maxSlidingWindow(nums []int, k int) []int {
	q := []int{} // 双端队列：存下标，对应值从队头到队尾单调递减
	res := []int{}
	for i, x := range nums {
		// ① 入队（队尾）：把所有 ≤ x 的下标弹掉——它们不可能再当最大值
		for len(q) > 0 && nums[q[len(q)-1]] <= x {
			q = q[:len(q)-1] // 弹出队尾
		}
		q = append(q, i)
		// ② 出队（队头）：队头下标已滑出窗口左边界（≤ i-k），过期清理
		if q[0] <= i-k {
			q = q[1:]
		}
		// ③ 窗口形成后（i ≥ k-1），队头就是当前窗口最大值
		if i >= k-1 {
			res = append(res, nums[q[0]])
		}
	}
	return res
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 每个下标最多入队 1 次 + 出队 1 次，均摊 O(1)/步 |
| 空间 | O(k) | 队列里最多同时存 k 个下标 |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 暴力扫每个窗口 | O(n·k) | O(1) | k 大时直接超时 |
| 大顶堆（懒删除） | O(n log n) | O(n) | 能过，但要处理过期堆顶，代码绕 |
| 单调队列 | O(n) | O(k) | 最优，"滑动窗口最值"的标准答案 |

### 易错点

1. **队列存值不存下标**：无法判断队头是否滑出窗口，必须存下标（值可以通过 `nums[下标]` 随时取）。
2. **忘记清理过期队头**：队头下标 `≤ i-k` 就已经不在窗口 `[i-k+1, i]` 里了，取答案前要先弹掉。
3. **`i >= k-1` 才开始写答案**：前 k-1 步窗口还没装满，不能输出。
4. **弹队尾用 `<` 还是 `<=`**：两者都对，用 `<=`（相等也弹）能让队列更短，更推荐。
5. **Go 没有内置 deque**：用切片模拟，`q = q[:len(q)-1]` 弹尾、`q = q[1:]` 弹头即可，注意这种写法会导致底层数组无法复用，但本题规模下没问题。

> 🎤 **口述模板**
> 「暴力是每个窗口扫一遍 O(n·k)，我优化到 O(n) 用单调队列：队列里存下标，保证对应的值从队头到队尾递减，队头永远是当前窗口最大值。新元素入队前，把队尾所有比它小的都弹掉——因为它们比新元素小还比新元素先过期，永远当不上最大值；队头如果下标滑出窗口左边界就弹掉。每个元素最多进出队列各一次，所以总时间是 O(n)，空间 O(k)。」

## 三、LC76 最小覆盖子串（困难）

### 题干简述

- **LeetCode 76. 最小覆盖子串**，难度：困难
- 给你字符串 `s` 和 `t`，返回 `s` 中**涵盖 `t` 所有字符（含重复个数）的最短子串**；不存在则返回空串 `""`。

```
示例：s = "ADOBECODEBANC", t = "ABC" → 输出 "BANC"

（"ADOBEC" 也涵盖 A、B、C，但长度 6；"BANC" 长度 4，更短）
```

### 解题思路：滑动窗口的"欠账"记法

**先确认这题能用滑动窗口**（和 LC560 对比着记）：
窗口里多塞一个字符，只会"更有希望"覆盖 t，不会变差——**扩大无损，缩小有界**，单调性成立。
（LC560 是负数破坏单调性；这题字符只会攒不会亏，所以能滑。）

**窗口怎么记账？** 用"欠账"计数，只需要两个变量 + 一个数组：

- `need[c]`：字符 `c` 还欠几个（正数 = 欠着，负数 = 有盈余）；
- `missing`：欠账总数，**等于 0 就代表窗口已覆盖 t**。

右指针吞字符、左指针吐字符时账本怎么变：

```
吞 s[right]（进窗口）：
    若 need[c] > 0（真的还缺它） → missing--
    need[c]--（欠账减一；不缺则变成负数，表示盈余 +1）

吐 s[left]（出窗口）：
    need[c]++（先还账）
    若 need[c] > 0（吐出了必需字符） → missing++，窗口又欠债了
```

**整体流程：右扩到"刚好不欠"→ 左缩到"再缩就欠"→ 记录答案 → 继续右扩**，
像一条毛毛虫蠕动前进：

```
s = "ADOBECODEBANC",  t = "ABC"

 A D O B E C O D E B A  N  C
 ├──────────┤            右扩到 C：第一次凑齐（missing=0），窗口 "ADOBEC"
   ...
                      B A N C
                       ├────┤ 左缩到极限，最短答案 "BANC"（长度 4）

右指针全程只前进、左指针全程只前进 → 各走 n 步，O(n)
```

**为什么左缩不会错过更优解？** 左缩的每一步都先检查 `missing == 0` 才缩，
缩到"再缩就欠账"为止时窗口是"以当前右端点结尾的最短可行窗口"，每种右端点都考察过，不漏。

### 代码

```go
package main

// LC76 最小覆盖子串：不定长窗口 + 欠账计数
func minWindow(s string, t string) string {
	need := [128]int{} // 字符只有 ASCII，用数组比 map 快
	for i := 0; i < len(t); i++ {
		need[t[i]]++
	}
	missing := len(t) // 总欠账：还差多少个字符才算覆盖
	bestL, bestLen := 0, len(s)+1
	left := 0
	for right := 0; right < len(s); right++ {
		c := s[right]      // 右端吞进一个字符
		if need[c] > 0 {   // 是真的还欠的字符，欠账减一
			missing--
		}
		need[c]-- // 不欠则变负数，表示窗口内该字符盈余 +1

		for missing == 0 { // 已凑齐，开始从左端收缩
			if right-left+1 < bestLen {
				bestLen = right - left + 1 // 记录更短的可行窗口
				bestL = left
			}
			d := s[left]
			need[d]++ // 吐出左端字符，先还账
			if need[d] > 0 { // 吐的是必需字符 → 窗口又不覆盖了
				missing++
			}
			left++
		}
	}
	if bestLen > len(s) { // 从没凑齐过
		return ""
	}
	return s[bestL : bestL+bestLen]
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(\|s\| + \|t\|) | 左右指针各单向走一遍，每步 O(1) |
| 空间 | O(128) = O(1) | 字符计数数组，与输入长度无关 |

### 解法对比表

| 解法 | 时间 | 一句话点评 |
|------|------|------------|
| 暴力枚举所有子串逐个检查 | O(n²·m) | 想都别想，面试直接跳过 |
| need/window 双哈希逐字符判相等 | O(n) | 每步扫 256 个字符判 valid，慢一个常数但好记 |
| 欠账计数（本解法） | O(n) | missing 一个变量判可行，最优雅 |

### 易错点

1. **每步逐字符比较 need 和 window**：能过但多余——用一个 `missing` 总欠账变量，判可行只要 O(1)。
2. **吞字符时先 `need[c]--` 再判断**：顺序反了就区分不了"真缺"和"盈余"，正确逻辑是先看 `need[c] > 0` 再减。
3. **吐字符时忘了 `need[d]++` 后再判断 `> 0`**：还账和欠账的方向别搞反。
4. **无解情况**：`bestLen` 要初始化成"不可能的大"（`len(s)+1`），最后没更新就返回 `""`。
5. **遍历 string 用 `for i := range s` 拿到的是 rune 下标**：本题字符集是 ASCII，直接 `s[i]` 按字节处理即可（按 rune 反而会出错）。

> 🎤 **口述模板**
> 「困难题 76 我用滑动窗口加欠账计数。先用长度 128 的数组统计 t 里每个字符还欠几个，再用一个 missing 变量记总欠账。右指针不断吞字符：如果这个字符还欠着，欠账减一；欠账归零说明窗口已覆盖 t，就开始收缩左端，边缩边更新最短答案，直到再缩就不够为止。左右指针各走一遍，时间 O(s+t)，空间 O(128) 常数。关键是判可行不用逐字符比较，看 missing 是不是零就行。」
