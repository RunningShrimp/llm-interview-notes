## 一、LC53 最大子数组和（中等）

### 题干简述

- **LeetCode 53. 最大子数组和**，难度：中等
- 给你一个整数数组 `nums`，找出**元素和最大的连续子数组**（子数组至少包含一个元素），返回其最大和。

```
示例：nums = [-2,1,-3,4,-1,2,1,-5,4] → 输出 6
      （连续子数组 [4,-1,2,1] 的和最大，为 6）
```

### 解题思路：一个变量滚出来的 DP

定义 DP：**`dp[i]` = 必须以 `nums[i]` 结尾的最大子数组和**。

为什么强行规定"以 i 结尾"？因为子数组必须**连续**——只有锁死右端点，
状态转移才有明确的"上一个状态"：`dp[i-1]`（以 i-1 结尾的最优）。

站在 `nums[i]` 面前只有两个选择：

```
选择 A：接在 dp[i-1] 后面 → dp[i] = dp[i-1] + nums[i]
选择 B：抛开过去，自己另起炉灶 → dp[i] = nums[i]

判断标准：dp[i-1] 是正是负？
  dp[i-1] ≥ 0 → 前面的累计是"正贡献"，白捡，接上
  dp[i-1] < 0  → 背袱！背着它只会拖累我，果断从自己重新开始

全局答案 = max(所有 dp[i])，因为最优子数组的右端点总落在某个 i 上
```

**空间优化**：转移只依赖 `dp[i-1]`，拿一个变量 `cur` 滚动即可，不用开数组。

### 代码

```go
package main

// LC53 最大子数组和：一维 DP，滚动变量版
func maxSubArray(nums []int) int {
	cur, best := nums[0], nums[0] // cur = 以当前元素结尾的最大和
	for i := 1; i < len(nums); i++ {
		if cur >= 0 { // 前面的累计是正贡献，带着走
			cur += nums[i]
		} else { // 是包袱，果断另起炉灶
			cur = nums[i]
		}
		if cur > best {
			best = cur
		}
	}
	return best
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 一趟扫描 |
| 空间 | O(1) | 只有 cur、best 两个变量（DP 数被滚动掉了） |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 暴力枚举区间 | O(n²) | O(1) | 面试保底 |
| 一维 DP / 滚动变量 | O(n) | O(1) | 标准答案，就是 Kadane 算法 |
| 前缀和 + 维护最小前缀 | O(n) | O(1) | 同样 O(n)，思路绕一点，可与 LC560 串联 |

### 易错点

1. **best 初始化成 0**：全负数组（如 `[-3,-1,-2]`）答案是 -1 而不是 0——子数组**至少选一个元素**，`cur`、`best` 都要用 `nums[0]` 初始化。
2. **DP 状态定义少了"以 i 结尾"**：定义成"前 i 个数的最大和"转移时连续性就断了。
3. **返回值忘了取全局 max**：dp[n-1] 不是答案，最优子数组可能结束在中间任何位置。

> 🎤 **口述模板**
> 「我用一维 DP：定义 dp[i] 是必须以 nums[i] 结尾的最大子数组和。转移只看 dp[i-1] 的正负——是正数就接上（白赚的贡献），是负数就从 nums[i] 另起炉灶，因为负的累计只会拖累后面。全局答案取所有 dp[i] 的最大值。由于只依赖上一个状态，用一个变量滚动，空间 O(1)，时间 O(n)。这就是 Kadane 算法。注意 best 要用 nums[0] 初始化，防止全负数组。」

## 二、LC56 合并区间（中等）

### 题干简述

- **LeetCode 56. 合并区间**，难度：中等
- 给定一堆闭区间 `intervals`，合并所有**有重叠**的区间，返回不重叠的区间列表。

```
示例：intervals = [[1,3],[2,6],[8,10],[15,18]]
     → [[1,6],[8,10],[15,18]]
     （[1,3] 和 [2,6] 重叠 → 合并为 [1,6]；其余互不相连）
```

### 解题思路：排序之后只剩"比右端点"

**乱序时的困境**：区间东一个西一个，判断谁和谁重叠要两两比对，O(n²)。

**排序破局**：按**左端点**升序排序后，局面立刻简化——
当前区间 `p` 的左端点，**只可能 ≥ 结果里最后一个区间的左端点**。
于是 `p` 和"上一段"的关系只有两种：

```
排序后（按左端点）：

 |—1,3—|
        |—2,6—|        ← p[0]=2 ≤ 上一段右端点 3 → 重叠！
                 |—8,10—|
                          |—15,18—|   ← p[0]=8 > 上一段右端点 6 → 分开

重叠时怎么合并？右端点取 max：
 上一段=[1,3]，p=[2,6] → max(3,6)=6 → [1,6] ✓
 上一段=[1,10]，p=[2,3] → max(10,3)=10 → [1,10]（被完全包含的情况！）
```

两种情况一句话：**`p[0] <= lastRight` 就合并（右端点取 max），否则另起一段**。

### 代码

```go
package main

import "sort"

// LC56 合并区间：按左端点排序 + 端点比较
func merge(intervals [][]int) [][]int {
	sort.Slice(intervals, func(i, j int) bool {
		return intervals[i][0] < intervals[j][0] // 按左端点升序
	})
	res := [][]int{}
	for _, p := range intervals {
		n := len(res)
		if n > 0 && p[0] <= res[n-1][1] { // 与最后一段重叠（左端点 ≤ 其右端点）
			if p[1] > res[n-1][1] { // 右端点只可能被拉得更远
				res[n-1][1] = p[1]   // 注意：合并成更长的区间
			}
		} else { // 和谁都不重叠，开新区间
			res = append(res, []int{p[0], p[1]})
		}
	}
	return res
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n log n) | 排序主导；合并本身只 O(n) |
| 空间 | O(log n)~O(n) | 排序递归栈/结果数组（结果一般不计入） |

### 解法对比表

| 解法 | 时间 | 一句话点评 |
|------|------|------------|
| 两两比较合并直到不动 | O(n²) | 想清楚重叠关系前别硬写 |
| 排序 + 一次扫描 | O(n log n) | 标准答案，所有区间题的第一反应 |

### 易错点

1. **忘排序或按右端点排序**：整套逻辑建立在"左端点有序"上，乱了全崩。
2. **合并时右端点直接覆盖**：`res[n-1][1] = p[1]` 不取 max，遇到**完全包含**的区间（`[1,10]` 后来了 `[2,3]`）会把 10 改成 3，答案错。
3. **判断重叠用 `<` 而不是 `<=`**：闭区间 `[1,3]` 和 `[3,5]` 在端点 3 相触，**算重叠**要合并。
4. **直接 append p 进结果**：`p` 引用的是原数组，后续修改会互相污染，要拷贝成新切片 `[]int{p[0], p[1]}`。

> 🎤 **口述模板**
> 「先按左端点排序，这样每个新区间只可能和结果里的最后一段重叠，不用回头看。扫一遍：如果当前区间的左端点 ≤ 最后一段的右端点，说明重叠，右端点取两者 max 合并进去——取 max 是为了处理完全包含的情况；否则当前区间另起一段。时间 O(n log n)，排序是瓶颈，合并本身线性。」

## 三、LC189 轮转数组（中等）

### 题干简述

- **LeetCode 189. 轮转数组**，难度：中等
- 给定整数数组 `nums`，将数组中的元素**向右轮转 `k` 个位置**，其中 `k` 是非负数。要求**原地**（O(1) 额外空间）。

```
示例：nums = [1,2,3,4,5,6,7], k = 3
     → [5,6,7,1,2,3,4]（最后 3 个挪到最前面）
```

### 解题思路：三次翻转的魔法

**朴素做法**：开个新数组，`(i+k) % n` 放过去——但 O(n) 空间，不满足原地。
**环状替换**：每个数直接跳到目的地，走 k 条环——能 O(1) 空间，但下标绕死人，面试现场极易写错。
**三次翻转**：又短又稳，还特别好讲。

把数组看成两段 `A | B`（A 是前 n-k 个，B 是后 k 个）。右转 k 就是把 `B` 挪到 `A` 前面变成 `B | A`。
而"两段互换位置"恰好可以靠三次翻转完成：

```
原数组:        [1 2 3 4 | 5 6 7]      目标: [5 6 7 | 1 2 3 4]
                \___A___/ \_B_/

① 整体翻转:    [7 6 5 | 4 3 2 1]      ← B⁻¹ 和 A⁻¹ 都"倒着"站
② 翻转前 k 个:  [5 6 7 | 4 3 2 1]      ← B 归位 ✓，A 还是倒的
③ 翻转剩余的:   [5 6 7 | 1 2 3 4]      ← A 也归位，完成 ✓
```

直觉：**"倒着放的两段"各自再翻一次正回来**。翻转本身是双指针交换，原地 O(n)。

### 代码

```go
package main

// LC189 轮转数组：三次翻转法，原地 O(1) 空间
func rotate(nums []int, k int) {
	n := len(nums)
	k %= n // k 可能远大于 n，先取模
	reverseRange(nums, 0, n-1) // ① 整体翻转
	reverseRange(nums, 0, k-1) // ② 翻转前 k 个（原数组的尾部）
	reverseRange(nums, k, n-1) // ③ 翻转剩下的（原数组的头部）
}

// 反转 a[l..r]，双指针对向交换
func reverseRange(a []int, l, r int) {
	for l < r {
		a[l], a[r] = a[r], a[l]
		l++
		r--
	}
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 三次翻转，每个元素被交换约 1.5 次 |
| 空间 | O(1) | 纯原地，只用 l/r 下标 |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 辅助数组直接放 | O(n) | O(n) | 最好写，但题目点名要原地 |
| 环状替换 | O(n) | O(1) | 理论漂亮，下标绕、易写错 |
| 三次翻转 | O(n) | O(1) | 原地 + 好写好讲，面试首选 |

### 易错点

1. **忘 `k %= n`**：k = 10、n = 7 时直接越界或白转。
2. **翻转区间写错**：② 是 `[0, k-1]`，③ 是 `[k, n-1]`，别把 k 当成"长度"和"下标"搞混。
3. **左旋右旋分不清**：右转 k = 尾部 k 个挪到头；左转 k = 头部 k 个挪到尾（等价右转 n-k，三次翻转的切分点跟着变）。
4. **reverse 边界 `l < r` 写成 `l <= r`**：中间那个元素自己和自己换不报错，但中点判断习惯要养对。

> 🎤 **口述模板**
> 「原地轮转我用三次翻转：右转 k 位，本质是把数组切成前 n-k 和后 k 两段然后互换位置。先整体翻转，两段各自都倒过来了；再翻转前 k 个和后 n-k 个，分别把它们正回来，就得到结果。比如 1 2 3 4 5 6 7 右转 3：整体翻成 7 6 5 4 3 2 1，前 3 个翻成 5 6 7，后面翻成 1 2 3 4。注意先 k 取模 n。时间 O(n)，空间 O(1)。」

## 四、LC238 除自身以外数组的乘积（中等）

### 题干简述

- **LeetCode 238. 除自身以外数组的乘积**，难度：中等
- 给定整数数组 `nums`，返回 `res[i] = nums 中除 nums[i] 之外所有元素的乘积`。
- **不允许使用除法**，且要求 O(n)（进阶：O(1) 额外空间，输出数组不算）。

```
示例：nums = [1,2,3,4] → [24,12,8,6]
      （24 = 2×3×4，12 = 1×3×4，8 = 1×2×4，6 = 1×2×3）
```

### 解题思路：左半边 × 右半边

第一反应"总积除以自己"被两件事否决：题目明令禁止除法；而且**一旦有 0，除法直接崩**（0 不能当分母，多个 0 还得特判）。

换个角度拆乘积：**除掉 nums[i]，剩下的 = i 左边所有的积 × i 右边所有的积**。

```
i =          0     1     2     3
nums:        1     2     3     4
左积 L[i]:   1     1     2     6      ← L[i] = nums[0..i-1] 的积（L[0]=1，左边没数）
右积 R[i]:  24    12     4     1      ← R[i] = nums[i+1..n-1] 的积（R[n-1]=1）
res[i] = L[i] × R[i]:
            1×24  1×12  2×4   6×1
             ↓     ↓     ↓     ↓
            24    12    8     6 ✓
```

两趟遍历：第一趟从左往右把 L 乘进 `res`；第二趟从右往左，用一个变量 `right`
滚动维护后缀积，边走边乘——连 R 数组都省了，额外空间 O(1)。

### 代码

```go
package main

// LC238 除自身以外数组的乘积：前后缀分解
func productExceptSelf(nums []int) []int {
	n := len(nums)
	res := make([]int, n)
	res[0] = 1
	for i := 1; i < n; i++ { // 第一趟：res[i] = 左边所有数的积
		res[i] = res[i-1] * nums[i-1]
	}
	right := 1 // 滚动的后缀积
	for i := n - 1; i >= 0; i-- { // 第二趟：从右往左乘上右边所有数的积
		res[i] *= right
		right *= nums[i]
	}
	return res
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 两趟线性扫描 |
| 空间 | O(1) | 输出数组不计，只用 right 一个变量 |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 总积 ÷ nums[i] | O(n) | O(1) | 被禁止 + 有 0 直接崩 |
| 左积、右积两个数组 | O(n) | O(n) | 思路最直白 |
| 输出数组复用两趟 | O(n) | O(1) | 标准答案，面试说出来加分 |

### 易错点

1. **`res[0] = 1` 别忘**：左边没有元素，乘积定义为 1（乘法单位元）。
2. **第二趟方向**：必须从右往左，`right` 滚动才表示"i 右边的积"；写反后缀就串了。
3. **先 `res[i] *= right` 再 `right *= nums[i]`**：顺序反了会把 nums[i] 自己乘进去。

> 🎤 **口述模板**
> 「不能用除法，我就把每个位置的结果拆成左半边积乘右半边积。第一趟从左往右，把每个 i 左边所有元素的乘积存进结果数组；第二趟从右往左，用一个变量滚动维护后缀积，边走边乘到结果上，这样连右积数组都省了。两趟 O(n)，除输出外额外空间 O(1)。有 0 也天然没问题，因为压根没用除法。」

## 五、LC41 缺失的第一个正数（困难）

### 题干简述

- **LeetCode 41. 缺失的第一个正数**，难度：困难
- 给定一个**未排序**的整数数组，找出**没有出现在数组中的最小正整数**。
- 要求时间 O(n)，且只使用常数级额外空间。

```
示例 1：[1,2,0]      → 3（1、2 都在，缺 3）
示例 2：[3,4,-1,1]   → 2
示例 3：[7,8,9,11,12]→ 1（1 都没出现，最小缺失就是 1）
```

### 解题思路：把数组自己当哈希表

**两个朴素方案都被复杂度卡死**：排序后扫 → O(n log n)；哈希表 → O(n) 空间。

**先缩小答案范围（鸽笼原理）**：数组长度 n，最小缺失正数**一定落在 `[1, n+1]`**——
如果 1..n 全都在，答案是 n+1；否则答案就是 1..n 里第一个缺席的。
负数、0、大于 n 的数全是"废子"，可以无视。

**核心一招：原地哈希（数字归位）**——值 `v`（1 ≤ v ≤ n）的"家"就是下标 `v-1`：

```
约定：值 v 应该住进下标 v-1（1 住 0 号位，2 住 1 号位……）

nums = [3, 4, -1, 1]     归位过程：

i=0: nums[0]=3 不在家(家住下标2)，把 3 送回 2 号位 → [-1, 4, 3, 1]
     换回来的 -1 是废子，不管
i=1: nums[1]=4 不在家(家住下标3)，送回 3 号位       → [-1, 1, 3, 4]
     换回来的 1 不在家(家住下标0)，再送回 0 号位    → [1, -1, 3, 4]
     换回来的 -1 废子，不管
i=2: nums[2]=3 已在家 ✓
i=3: nums[3]=4 已在家 ✓

最后扫一遍：下标 1 住的是 -1，不是 2 → 答案 = 2 ✓
```

**为什么是 O(n) 不是 O(n²)？** 看似双重循环，但**每一次交换都恰好让一个数字永久到家**，
整个过程的交换总次数 ≤ n，加上外层 n 次判断，均摊下来就是 O(n)。

### 代码

```go
package main

// LC41 缺失的第一个正数：原地哈希（数字归位）
func firstMissingPositive(nums []int) int {
	n := len(nums)
	for i := 0; i < n; i++ {
		// 当前位置坐的不是"属于这里的数"，且来的客人是有效住户(1..n)、
		// 且目标位置上还没住着同一个人 → 持续交换，把它送回家
		for nums[i] >= 1 && nums[i] <= n && nums[nums[i]-1] != nums[i] {
			// Go 多重赋值：右侧先用旧值求值，安全完成交换
			nums[i], nums[nums[i]-1] = nums[nums[i]-1], nums[i]
		}
	}
	for i := 0; i < n; i++ { // 第一个"位子上没有对号入座"的地方
		if nums[i] != i+1 {
			return i + 1
		}
	}
	return n + 1 // 1..n 全齐，缺的是 n+1
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n) | 交换总次数 ≤ n（每次交换固定归位一个数），均摊线性 |
| 空间 | O(1) | 数组本身当哈希表，零额外空间 |

### 解法对比表

| 解法 | 时间 | 空间 | 一句话点评 |
|------|------|------|------------|
| 排序后线性扫 | O(n log n) | O(1) | 时间超标 |
| 哈希表记录出现过的数 | O(n) | O(n) | 空间超标 |
| 原地哈希（归位） | O(n) | O(1) | 双达标，"困难"就难在想到它 |

### 易错点

1. **循环条件少 `nums[nums[i]-1] != nums[i]`**：遇到重复元素（如 `[1,1]`）会无限交换死循环——目标位已经住着"同一个人"时就别换了。
2. **交换写成三行临时变量**：`tmp := nums[i]; nums[i] = nums[nums[i]-1]; nums[nums[i]-1] = tmp`——第二步执行后 `nums[i]` 已经变了，第三步的下标跟着错。Go 的多重赋值一行搞定；C++/Java 也要先算好两个下标。
3. **忘记排除废子**：`nums[i]` 不在 `[1, n]` 范围内（负数、0、超大数）直接跳过，别去交换。
4. **答案上界想成 n**：1..n 全部在场时答案是 **n+1**，最后要 `return n + 1`。

> 🎤 **口述模板**
> 「困难点在 O(n) 时间加 O(1) 空间。先由鸽笼原理把答案锁定在 1 到 n+1 之间，因为长度 n 的数组最多装下 1 到 n。然后做原地哈希：遍历数组，只要当前位置的值 v 在 1 到 n 之间、并且它家里（下标 v-1）住的不是它自己，就交换把它送回家，直到位置上是废子或已归位。每次交换必然让一个数永久到家，所以总交换次数不超过 n，均摊 O(n)。最后扫一遍，第一个下标 i 上不是 i+1 的位置，答案就是 i+1；全都对号入座就返回 n+1。注意判重条件防死循环。」
