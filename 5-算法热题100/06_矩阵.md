# 矩阵：标记、边界、翻转与阶梯

> 矩阵题的代码都不长，**难的是下标不写错**。
> 这组四道题各有一个"防错骨架"：LC73 用首行首列当标记板，LC54 四边界收缩，
> LC48 转置加翻转两步走，LC240 从右上角走阶梯。骨架记牢，下标自然稳。

## 本组题目总览

| # | 题号 | 题目 | 核心考点 | 难度 |
|---|------|------|----------|------|
| 1 | LC73  | 矩阵置零 | 首行首列标记法（O(1) 空间） | 中等 |
| 2 | LC54  | 螺旋矩阵 | 四边界收缩模拟 | 中等 |
| 3 | LC48  | 旋转图像 | 转置 + 翻转两步法 | 中等 |
| 4 | LC240 | 搜索二维矩阵 II | 右上角起点（Z 形/阶梯查找） | 中等 |

先说一个贯穿全组的事实：Go 里 `matrix[i]` 是第 i **行**（横向），`matrix[i][j]` 是第 i 行第 j **列**。
写矩阵题时嘴里默念"先行后列"，能少一半下标事故。

## 一、LC73 矩阵置零（中等）

### 题干简述

- **LeetCode 73. 矩阵置零**，难度：中等
- 给定一个 `m × n` 矩阵，如果一个元素为 **0**，则将其**所在行和所在列**的所有元素都设为 0。
- 要求**原地**（进阶：使用 O(1) 额外空间）。

```
示例：[1,1,1]        [1,0,1]
      [1,0,1]   →    [0,0,0]
      [1,1,1]        [1,0,1]
（中间那个 0，把第 2 行和第 2 列全染成 0）
```

### 解题思路：让第一行第一列自己当"留言板"

**朴素方案**：开 `row[m]`、`col[n]` 两个标记数组，先扫一遍记录哪些行、列要置零，再刷一遍。O(m+n) 空间，好写。

**原地化的脑洞**：标记信息总得有地方放——那就**借用第一行和第一列本身**：

- `matrix[i][0] = 0` → 第 i 行要置零；
- `matrix[0][j] = 0` → 第 j 列要置零。

但有个先有鸡还是先有蛋的问题：**第一行、第一列自己的命运由谁记录？**
它们已经被借用作留言板，会被"业务数据"污染。所以要用两个布尔变量，在打标记**之前**先把第一行/第一列自己有没有 0 记下来。

```
步骤（顺序不能乱！）：

① 先记录：第一行自己有 0 吗？→ firstRowZero
          第一列自己有 0 吗？→ firstColZero
② 再打标记：扫内部 [1..m-1][1..n-1]，遇到 0 就在
          对应的 matrix[i][0] 和 matrix[0][j] 留言
③ 依据留言刷内部（只刷 [1..]，别碰留言板本身）
④ 最后按 ① 的记录刷第一行、第一列
```

### 代码

```go
package main

// LC73 矩阵置零：首行首列当标记板，O(1) 额外空间
func setZeroes(matrix [][]int) {
	m, n := len(matrix), len(matrix[0])
	firstRowZero, firstColZero := false, false

	for j := 0; j < n; j++ { // ① 第一行自己有没有 0
		if matrix[0][j] == 0 {
			firstRowZero = true
			break
		}
	}
	for i := 0; i < m; i++ { // ① 第一列自己有没有 0
		if matrix[i][0] == 0 {
			firstColZero = true
			break
		}
	}
	for i := 1; i < m; i++ { // ② 内部扫一遍，往首行/首列留言
		for j := 1; j < n; j++ {
			if matrix[i][j] == 0 {
				matrix[i][0] = 0 // 第 i 行要置零
				matrix[0][j] = 0 // 第 j 列要置零
			}
		}
	}
	for i := 1; i < m; i++ { // ③ 按留言刷内部区域
		for j := 1; j < n; j++ {
			if matrix[i][0] == 0 || matrix[0][j] == 0 {
				matrix[i][j] = 0
			}
		}
	}
	if firstRowZero { // ④ 最后处理第一行自己
		for j := 0; j < n; j++ {
			matrix[0][j] = 0
		}
	}
	if firstColZero { // ④ 最后处理第一列自己
		for i := 0; i < m; i++ {
			matrix[i][0] = 0
		}
	}
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(m·n) | 两次全矩阵扫描 |
| 空间 | O(1) | 只有两个布尔变量（首行首列是"免费"的留言板） |

### 解法对比表

| 解法 | 空间 | 一句话点评 |
|------|------|------------|
| 收集所有 0 的坐标再刷 | O(k) | 直白但空间不受控 |
| row/col 两个标记数组 | O(m+n) | 标准写法，面试先说这个再优化 |
| 首行首列标记 | O(1) | 进阶答案，靠两个布尔变量补盲区 |

### 易错点

1. **顺序颠倒**：先打标记再记第一行/列状态，留言板已经被污染，firstRowZero/firstColZero 永远失真。必须"先记录、后留言、再刷漆、最后刷首行首列"。
2. **刷内部时从 0 开始**：把留言板本身刷了，标记信息提前丢失。
3. **m 和 n 用反**：`m` 是行数 `len(matrix)`，`n` 是列数 `len(matrix[0])`。
4. **只有一行/一列的矩阵**：本解法天然兼容（内部区域为空，循环不执行），但要确认别把 ①② 的边界写歪。

> 🎤 **口述模板**
> 「最直接的思路是用两个标记数组记哪些行列要置零，O(m+n) 空间。进阶做到 O(1)：把第一行和第一列借来当标记板——内部某个格子是 0，就在它所在行的第一列、所在列的第一行写 0。关键细节是第一行第一列自己的命运没法记在自己身上，所以先用两个布尔变量在打标记之前把"它们自己含不含 0"记下来，最后再统一刷。顺序必须是：先记录、再打标记、刷内部、最后刷首行首列。」

## 二、LC54 螺旋矩阵（中等）

### 题干简述

- **LeetCode 54. 螺旋矩阵**，难度：中等
- 给你一个 `m × n` 矩阵，按**顺时针螺旋顺序**返回所有元素。

```
示例：[1,2,3]          输出：[1,2,3,6,9,8,7,4,5]
      [4,5,6]
      [7,8,9]

  ┌─────────────┐
  │ 1 → 2 → 3   │   走到头拐弯：
  │         ↓   │   →  ↓  ←  ↑  一圈四个方向
  │ 7 ← 8 ← 9   │
  └─────────────┘
```

### 解题思路：四条边界，走一条缩一条

不要去想"下一个格子坐标怎么算"的方向模拟（dx/dy 转向），那是给自己埋雷。
更稳的骨架是**维护四个边界**：`top`、`bottom`、`left`、`right`，
每一圈按固定顺序走四条边，**走完一条边，对应边界向内收缩一格**：

```
        left                right
         ↓                   ↓
top  →   ┌──→──→──→──┐      ① 上边：left → right 走完，top++
         │            │
         ↑            ↓      ② 右边：top → bottom 走完，right--
         │            │
bottom   └──←──←──←──┘      ③ 下边：right → left 走完，bottom--
                                ④ 左边：bottom → top 走完，left++

圈与圈之间无缝衔接，边界一旦交叉（left > right 或 top > bottom）就收工
```

走一圈示例（3×4 矩阵）：

```
[ 1  2  3  4]
[ 5  6  7  8]      第一圈: ①1 2 3 4  ②8 12  ③11 10 9  ④5
[ 9 10 11 12]      收缩后剩 6 7 这个 1×2 核心，走 ① 6 7 结束
```

**唯一的坑：最后剩"一行"或"一列"时**，四条边会重复走同一批格子
（比如只剩一行，①走完了 ③ 又把同一行倒着走一遍）。
所以走完 ①② 之后要检查 `top > bottom || left > right`，提前 break。

### 代码

```go
package main

// LC54 螺旋矩阵：四边界收缩
func spiralOrder(matrix [][]int) []int {
	top, bottom := 0, len(matrix)-1
	left, right := 0, len(matrix[0])-1
	res := []int{}
	for left <= right && top <= bottom {
		for j := left; j <= right; j++ { // ① 上边：从左到右
			res = append(res, matrix[top][j])
		}
		top++
		for i := top; i <= bottom; i++ { // ② 右边：从上到下
			res = append(res, matrix[i][right])
		}
		right--
		if top > bottom || left > right { // 只剩一行/一列，防重复
			break
		}
		for j := right; j >= left; j-- { // ③ 下边：从右到左
			res = append(res, matrix[bottom][j])
		}
		bottom--
		for i := bottom; i >= top; i-- { // ④ 左边：从下到上
			res = append(res, matrix[i][left])
		}
		left++
	}
	return res
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(m·n) | 每个元素恰好被访问一次 |
| 空间 | O(1) | 结果数组不计，只有四个边界变量 |

### 解法对比表

| 解法 | 一句话点评 |
|------|------------|
| 方向数组模拟转向 | 也能对，但"什么时候转向、什么时候停"的判断写起来心虚 |
| 四边界收缩（本解法） | 四个变量 + 固定四循环，最不容易写错 |

### 易错点

1. **没有 ② 之后的 break**：剩一行或一列时 ③④ 会把 ①② 刚走过的格子再走一遍，输出重复元素——这是本题最经典的 bug。
2. **边界更新漏写**：每条边的 for 循环后面紧跟对应 `top++/right--/bottom--/left++`，少一个直接死循环或越界。
3. **`<=` 写成 `<`**：边界是**闭区间**，左右相等的那一列/行也要走。
4. **非方阵不兼容的写法**：用"圈数 = min(m,n)/2"控制循环时，长方形矩阵尾部处理极易漏；四边界写法天然支持 m≠n。

> 🎤 **口述模板**
> 「我用四个变量维护上下左右边界，每圈固定走四条边：上边从左到右、右边从上到下、下边从右到左、左边从下到上，走完一条边就把对应边界向内收缩一格。关键细节是走完上和右之后要判断边界是否已经交叉——当矩阵只剩一行或一列时，后面的两条边会把同一批元素重复走一遍，需要提前退出。每个元素访问一次，时间 O(m·n)，空间 O(1)。」

## 三、LC48 旋转图像（中等）

### 题干简述

- **LeetCode 48. 旋转图像**，难度：中等
- 给定一个 `n × n` 二维矩阵，将其**顺时针旋转 90°**，要求**原地**（不能开新矩阵）。

```
示例：[1,2,3]        [7,4,1]
      [4,5,6]   →    [8,5,2]
      [7,8,9]        [9,6,3]
```

### 解题思路：一步到位太绕，拆成两步就简单

**直接旋转**的做法是"四点一组轮转"：`(i,j) → (j, n-1-i)`，一圈四个位置 cyclic 交换。
数学上没错，但四个下标互相牵扯，现场写极容易绕晕（不信可以试试）。

**两步法**优雅得多——顺时针转 90° 恰好等于：

1. **沿主对角线转置**（`matrix[i][j]` ↔ `matrix[j][i]`）；
2. **每行左右翻转**。

```
原矩阵          ① 转置（沿 ↘ 主对角线）    ② 每行左右翻转
1 2 3              1 4 7                      7 4 1
4 5 6      ──►     2 5 8          ──►          8 5 2
7 8 9              3 6 9                      9 6 3
                   （行列互换）                （每行 reverse）
```

为什么等价？跟踪一个元素就明白：`(i,j)` 转置后到 `(j,i)`，
再行翻转，列 `i` 变成 `n-1-i`，最终落在 `(j, n-1-i)`——正是顺时针 90° 的落点 ✓。

顺手记一组对称结论（面试常变着考）：

```
顺时针 90° = 转置 + 行翻转
逆时针 90° = 转置 + 列翻转
旋转 180°  = 行翻转 + 列翻转（不用转置）
```

### 代码

```go
package main

// LC48 旋转图像：转置 + 每行翻转，两步原地完成顺时针 90°
func rotate(matrix [][]int) {
	n := len(matrix)
	for i := 0; i < n; i++ { // ① 沿主对角线转置（只动上三角！）
		for j := i + 1; j < n; j++ {
			matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
		}
	}
	for i := 0; i < n; i++ { // ② 每行左右翻转
		l, r := 0, n-1
		for l < r {
			matrix[i][l], matrix[i][r] = matrix[i][r], matrix[i][l]
			l++
			r--
		}
	}
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(n²) | 转置碰一半元素，翻转碰全部，各一趟 |
| 空间 | O(1) | 全部原地交换 |

### 解法对比表

| 解法 | 一句话点评 |
|------|------------|
| 新矩阵直接放 `res[j][n-1-i] = m[i][j]` | 十秒写出，但 O(n²) 空间不满足原地 |
| 四点一组 cyclic 交换 | 原地 O(1)，四个下标极易写错 |
| 转置 + 行翻转（本解法） | 原地 O(1)，两步各自简单，最推荐 |

### 易错点

1. **转置时 `j` 从 0 开始**：`matrix[i][j]` 和 `matrix[j][i]` 换过去又换回来，等于白干。上三角 `j = i+1` 起，每个对称对只换一次。
2. **转置 + 列翻转记反了**：那是逆时针 90°，方向恰好相反——考前把三条等式背熟。
3. **误用 LC189 的"整体翻转"**：那是一维数组轮转的三次翻转，这里是矩阵旋转，两码事。
4. **本题只保证方阵**：转置要求行列数相等；长方形"旋转"只能开新矩阵。

> 🎤 **口述模板**
> 「顺时针转 90 度我拆成两步：先沿主对角线转置，再每行左右翻转。跟踪一个元素可以验证：i,j 转置后到 j,i，行翻转后列变成 n-1-i，正好是顺时针 90 度的落点。两步都是原地双指针交换，空间 O(1)，时间 O(n²)。转置注意只走上三角，否则对称对会换两次等于没换。顺带一提，转置加列翻转就是逆时针 90 度。」

## 四、LC240 搜索二维矩阵 II（中等）

### 题干简述

- **LeetCode 240. 搜索二维矩阵 II**，难度：中等
- 给定 `m × n` 矩阵，满足：**每行从左到右升序，每列从上到下升序**。判断 `target` 是否存在。

```
示例矩阵（行升、列升，但行与行之间不保证衔接）：
[ 1  4  7 11 15]
[ 2  5  8 12 19]
[ 3  6  9 16 22]
[10 13 14 17 24]

target = 5 → true；target = 20 → false
```

⚠️ 注意和 **LC74** 的区别：LC74 是"展开成一维后整体单调"，可以纯二分；
本题**只在行内、列内有序**（上一行结尾可能比下一行开头还大），整体二分不成立。

### 解题思路：站在哪个角，决定了能不能"排除"

在这样一个"局部有序"的矩阵里找数，核心是**每比较一次，能否安全排除一行或一列**。

看四个角的性质：

```
左上（最小方向）: 右边、下边都比它大 → 比它大往哪走？两个方向都可能 ❌
右下（最大方向）: 左边、上边都比它小 → 比它小往哪走？两个方向都可能 ❌
右上: 左边都比它小（同行）、下边都比它大（同列）
      → 比 target 大：往左（整列更大，排除这一列）
      → 比 target 小：往下（整行更小，排除这一行）✓
左下: 对称同理 ✓
```

**从右上角出发**，每个点只有两条路可走，走一步排掉一行或一列，
轨迹像个"Z 字/阶梯"，最多 m+n 步出结果：

```
target = 5，从右上角 15 出发：

 1  4  7 [15] ← 15 > 5，整列都 ≥ 15？不，本列下方更大 → 排除这一列，左移
 2  5  8  12
 3  6  9  16
10 13 14  17

 1  4 [7]    ← 7 > 5 → 左移
 2  5  8
 ...
 1 [4]       ← 4 < 5，整行都 ≤ 4 → 排除这一行，下移
 2  5

 2 [5]       ← 命中！返回 true
```

### 代码

```go
package main

// LC240 搜索二维矩阵 II：右上角起点的阶梯查找
func searchMatrix(matrix [][]int, target int) bool {
	i, j := 0, len(matrix[0])-1 // 从右上角出发
	for i < len(matrix) && j >= 0 {
		v := matrix[i][j]
		if v == target {
			return true
		} else if v > target {
			j-- // 当前值偏大：本列下方只会更大，整列排除，左移
		} else {
			i++ // 当前值偏小：本行左边只会更小，整行排除，下移
		}
	}
	return false // 走出矩阵边界还没命中
}
```

### 复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 时间 | O(m + n) | 每步排除一行或一列，最多走 m+n 步 |
| 空间 | O(1) | 两个下标 |

### 解法对比表

| 解法 | 时间 | 一句话点评 |
|------|------|------------|
| 全量遍历 | O(m·n) | 没用上任何有序性 |
| 每行二分 | O(m log n) | 不错，但没有利用列有序 |
| 右上角阶梯查找 | O(m + n) | 一次比较排除一行/一列，最优走法 |

### 易错点

1. **想用整体二分**（把矩阵当一维数组 `matrix[mid/n][mid%n]`）：那是 LC74 的特权，本题行间不衔接，二分方向无法确定。
2. **起点选错**：左上、右下两个角的"邻居关系"是同大或同小，比较后走不动；必须右上或左下。
3. **方向记反**：右上角起点，"大左小下"；考场上盯着"当前值右边/下边谁更大"现推一遍，别硬背。
4. **忘判空**：`matrix` 或 `matrix[0]` 为空时 `len(matrix[0])-1` 直接 panic（LeetCode 保证非空，但工程习惯要有）。

> 🎤 **口述模板**
> 「这题行内升序、列内升序，但整体不单调，不能像 74 题那样纯二分。我从右上角出发做阶梯查找：右上角这个点很特殊，它左边的都比它小、下边的都比它大。当前值比 target 大就左移一步，等于排除掉一整列；比 target 小就下移一步，排除掉一整行。每步至少排一行或一列，最多 m+n 步，时间 O(m+n)，空间 O(1)。左下角对称也可以，但左上右下不行，因为往两个方向走的条件会重叠。」

## 本组收尾：矩阵题的三条军规

1. **下标先行后列**：`matrix[i][j]` 永远是第 i 行第 j 列，m=行数=len(matrix)，n=列数=len(matrix[0])。
2. **改动前先想顺序**：LC73 的"先记录再标记"、LC54 的"走一条缩一条"，顺序错了信息就被自己破坏。
3. **原地题想"借用自己"**：标记借用首行首列（LC73）、旋转借用转置加翻转（LC48）——额外空间 O(1) 的题，答案往往藏在矩阵自己身上。
