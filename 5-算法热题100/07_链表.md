## 1｜LC160 相交链表（简单）

**题干**：给两个单链表的头节点 `headA`、`headB`，它们可能在某处相交（相交后共用同一段尾巴）。找出相交起始节点；不相交返回 `nil`。要求不改链表，O(m+n) 时间、O(1) 空间。
### 解题思路：把"不等长"变成"等长"

这题唯一的矛盾是**两条链长度不一样**：若等长，从头同步走，指针第一次相等处就是交点（是同一节点，不是值相等）。解法：pa 走完 A 接着走 B，pb 走完 B 接着走 A——

```text
A:  a1 → a2 ↘
              c1 → c2 → nil       （a、b 是各自独有段，c 是公共段）
B:  b1 → b2 ↗
pa: a1 a2 c1 c2 nil | b1 b2 c1   ← 共 a+c+b 步，停在 c1
pb: b1 b2 c1 c2 nil | a1 a2 c1   ← 共 b+c+a 步，停在 c1
```

两边路程都是 `a+c+b` 步，**必然同时到达交点**；不相交时两边同时走到 `nil`（`nil == nil` 也成立），循环自然结束返回 `nil`，一个特判都不用写。（哈希表把 A 的节点存下来再扫 B 也能判，但 O(m) 空间；先数长度再对齐头部也行，但要两遍扫描——都不如互换赛道优雅。）

```go
package main

func getIntersectionNode(headA, headB *ListNode) *ListNode {
	if headA == nil || headB == nil {
		return nil
	}
	pa, pb := headA, headB // 两个指针各自出发
	for pa != pb {
		if pa == nil {
			pa = headB // 自己的路走完了 → 去走对方的路
		} else {
			pa = pa.Next
		}
		if pb == nil {
			pb = headA
		} else {
			pb = pb.Next
		}
	}
	return pa // 相遇点即交点；都走到 nil 时这里就是 nil
}
```

**复杂度**：时间 O(m+n)｜空间 O(1)

### 易错点

- 换赛道的判断是 `pa == nil`，不是 `pa.Next == nil`（少走一步，"路径等长"就碎了）
- 交点判断的是**指针相等**（同一个节点），不是值相等；都到 nil 退出即"不相交"
- 别用"把 A 尾接到 B 头再判环"的破坏性做法，题目禁止改链表

### 🎤 口述模板

> "核心是把不等长变成等长：pa 走完 A 接着走 B，pb 走完 B 接着走 A，总步数都是 a+c+b，必然同时到达交点；不相交就同时到达 nil，同样成立。时间 O(m+n)，空间 O(1)，一次遍历无特判。"

## 2｜LC206 反转链表（简单）

**题干**：给你单链表的头节点 `head`，反转链表并返回新头。链表界的"Hello World"，必须闭眼写对。
### 解题思路：三指针"掉头"

反转的本质是让每个节点的 `Next` 从"指向下一个"变成"指向上一个"，遍历时同时记住三个位置，**边走边掉头，prev 永远是已反转部分的头**：

```text
初始:  nil    1 → 2 → 3 → nil
       prev  curr
每轮:  ① next = curr.Next 先存后手 → ② curr.Next = prev 掉头 → ③④ prev/curr 双双前进
结束:  nil ← 1 ← 2 ← 3      curr == nil，prev 就是新头
```

### 代码（迭代版，主推）

```go
package main

func reverseList(head *ListNode) *ListNode {
	var prev *ListNode // 已反转部分的头，初始为 nil
	curr := head
	for curr != nil {
		next := curr.Next // ① 先存后手
		curr.Next = prev  // ② 掉头
		prev = curr       // ③ prev 前进一步
		curr = next       // ④ curr 前进一步
	}
	return prev // curr 走到 nil 时，prev 恰好是新头
}
```

### 代码（递归版，加分项）

```go
package main

func reverseListRecursive(head *ListNode) *ListNode {
	// 递归出口：空链表或单节点，反转后就是自己
	if head == nil || head.Next == nil {
		return head
	}
	// 先反转 head 后面的部分，newHead 一直是最终的新头
	newHead := reverseListRecursive(head.Next)
	head.Next.Next = head // head 的下一个节点（反转后的尾）反过来指向 head
	head.Next = nil       // head 变成新尾，断开旧指针，否则成环
	return newHead
}
```

| 维度     | 迭代版       | 递归版                |
|----------|--------------|-----------------------|
| 时间     | O(n)         | O(n)                  |
| 空间     | O(1)         | O(n) 递归栈           |
| 风险     | 无           | 长链表可能栈溢出      |
| 面试建议 | **主推**     | 主动提一嘴当加分项    |

### 易错点

- `next` 必须先存，掉头之后 `curr.Next` 就不是原来的下一个了
- 循环结束返回 `prev` 不是 `curr`（此时 curr 已是 nil）
- 递归版 `head.Next = nil` 不能写在 `head.Next.Next = head` 前面，否则 head.Next 已是 nil，再取 `.Next` 直接 panic

### 🎤 口述模板

> "迭代三指针 prev/curr/next：每轮先存 next，curr.Next 掉头指向 prev，再双双前进一步，curr 到 nil 时 prev 就是新头。时间 O(n) 空间 O(1)。递归版也能写，但空间 O(n) 有栈溢出风险，工程上优先迭代。"

## 3｜LC234 回文链表（简单）

**题干**：给你单链表头节点 `head`，判断是否回文链表。进阶：O(n) 时间 + O(1) 空间。
### 解题思路：数组回文的"链表版"

数组回文是双指针两头往中间夹，链表只能从头走，**怎么从尾部出发**？——把后半段反转，就能从"尾部"往中间走了。三板斧：**快慢指针找中点 → 反转后半段 → 两半比对**。（拷数组做是 O(n) 空间，面试官下一句必问"能 O(1) 吗"，直接上正解。）

```text
原链:  1 → 2 → 3 → 2 → 1
① 找中点:   前半 1 → 2 → 3    后半 2 → 1
② 反转后半: 前半 1 → 2 → 3    后半反转 1 → 2
③ 两头比对: 1 vs 1 ✓   2 vs 2 ✓   → 回文
```

```go
package main

func isPalindrome(head *ListNode) bool {
	if head == nil || head.Next == nil {
		return true
	}
	// ① 快慢指针找中点：循环结束后 slow 停在“前半段最后一个节点”
	slow, fast := head, head
	for fast.Next != nil && fast.Next.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
	}
	// ② 反转后半段（从 slow.Next 开始）
	var prev *ListNode
	curr := slow.Next
	for curr != nil {
		next := curr.Next
		curr.Next = prev
		prev = curr
		curr = next
	}
	// ③ 两半从两头向中间比对，后半更短，循环以 p2 为准
	p1, p2 := head, prev
	for p2 != nil {
		if p1.Val != p2.Val {
			return false
		}
		p1 = p1.Next
		p2 = p2.Next
	}
	return true
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- 找中点条件用 `fast.Next != nil && fast.Next.Next != nil`，slow 停在**前半段最后一个节点**，奇偶长度通吃（奇数的中间节点归前半且不用比）
- 比对循环以 `p2 != nil` 为准（后半 ≤ 前半），用 p1 会空指针
- 本解改了原链表（后半被反转），面试补一句"需要的话比对完再反转回去"是细节分

### 🎤 口述模板

> "链表没法从尾走，所以先把后半段反转：快慢指针找中点，slow 停在前半段最后一个；反转 slow 之后的部分；两个指针从两头逐个比对。O(n) 时间 O(1) 空间，代价是临时改了后半段，可再反转恢复。"

## 4｜LC141 环形链表（简单）

**题干**：给你头节点 `head`，判断链表中是否有环（尾部连接到链表中某下标）。不许改链表。
### 解题思路：操场追及问题

slow 一步 fast 两步。有环时 fast 先进环"套圈跑"，每轮和 slow 的**距离缩小 1**，距离模环长终会变 0——必然相遇（不会跨过：距离每次减 1，不会从 1 直接跳过 0）。无环则 fast 一路冲到 `nil`。哈希表存走过的节点也能判但 O(n) 空间，Floyd 判圈法 O(1) 空间完胜。

```text
        ┌──────── 环 ────────┐
        ↓                    │
        1 → 2 → 3 → 4 → 5 → 6
slow 一步 fast 两步：进环后每轮距离 -1，必然追上
```

```go
package main

func hasCycle(head *ListNode) bool {
	slow, fast := head, head
	for fast != nil && fast.Next != nil { // fast 要跳两步，先确认两步都存在
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast { // 追上了 → 有环
			return true
		}
	}
	return false // fast 冲到 nil → 无环
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- 循环条件 `fast != nil && fast.Next != nil`；`fast.Next.Next` 不用判——前两个成立时它必非 nil（跳两步前先看脚下两块地砖）
- 空链表、单节点：循环直接不进，天然返回 false
- 经典追问"fast 走 3 步行不行"：距离每次减 2 可能跨过 0（从 1 直接变 -1 错过相遇点）；走 2 步不会

### 🎤 口述模板

> "Floyd 判圈：slow 一步 fast 两步。进环后 fast 相对 slow 每轮逼近 1 步，距离一路减到 0 必然相遇；无环则 fast 先到 nil。O(n) 时间 O(1) 空间。追问也能答：fast 走 3 步可能跨过 slow，走 2 步不会。"

## 5｜LC142 环形链表 II（中等）⭐

**题干**：在 LC141 基础上升级：不仅判环，还要返回**环的入口节点**，无环返回 `nil`。
### 解题思路：相遇之后，数学登场

第一阶段同 LC141：快慢指针相遇确认有环。关键在第二阶段——**为什么"一个指针回到头部，两个同速前进，再相遇就是入口"**？设头到入口 `a`、入口到相遇点 `b`、相遇点绕回入口 `c`（环长 `L = b + c`）：

```text
head --- a ---> 入口 --- b ---> 相遇点
                ↑                │
                └────── c ───────┘        环长 L = b + c

slow 走了:  a + b
fast 走了:  a + b + n·L        （n 是 fast 多绕的圈数，n ≥ 1）
fast 是 slow 的 2 倍:
    2(a + b) = a + b + n·L
    a + b    = n·L
    a        = n·L - b = (n - 1)·L + c
```

结论 `a = (n-1)·L + c` 翻译成人话：**从 head 走 a 步**，和**从相遇点走 c 步再绕 (n-1) 整圈**，落点相同——都是入口。所以相遇后一个指针回 head，两个同速每轮各走一步，第一次相等处就是入口。这段推导白板画出来，直接和候选人拉开差距。

```go
package main

func detectCycle(head *ListNode) *ListNode {
	slow, fast := head, head
	for fast != nil && fast.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
		if slow == fast { // ① 判环成功，拿到相遇点
			// ② 一个指针回头部，和相遇点同速前进，再相遇即入口
			p := head
			for p != slow {
				p = p.Next
				slow = slow.Next
			}
			return p
		}
	}
	return nil // 无环
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- 第一阶段的相遇点**不是**入口，别拿到 `slow == fast` 就直接返回
- 第二阶段两个指针必须**同速、每轮都走**，不能一个走两步
- 推导记不住就记结论"一个回头部，同速前进，相遇即入口"，但建议把 `2(a+b)=a+b+nL` 练到肌肉记忆

### 🎤 口述模板

> "先快慢指针判环拿相遇点。设头到入口 a、入口到相遇点 b、相遇点回入口 c，fast 路程是 slow 两倍：2(a+b)=a+b+nL，化简得 a=(n-1)L+c。即从 head 走 a 步和从相遇点走 c 步（加整圈）落点相同，都是入口。所以一个指针回 head，两个同速前进，再相遇就是环入口。O(n) 时间 O(1) 空间。"

## 6｜LC143 重排链表（中等）

**题干**：给定单链表 `L: L0 → L1 → … → Ln-1 → Ln`，就地重排为 `L0 → Ln → L1 → Ln-1 → L2 → Ln-2 → …`（不能只改节点内部的值）。
### 解题思路：后半段反转后"拉链"

要"头取一个、尾取一个"，可链表拿不到尾——那就**把后半段反转**，变成两条都从头出发的链，交错合并。找中点、反转、合并全是前面练过的基本功，这题是**组合题**（暴力"每次取尾插前面"是 O(n²)，面试官说"优化一下"就是要这三步法）。

```text
原链:  1 → 2 → 3 → 4 → 5
① 找中点并断开:  1 → 2 → 3      4 → 5
② 反转后半:      1 → 2 → 3      5 → 4
③ 交错合并（拉链）: 1 → 5 → 2 → 4 → 3
```

```go
package main

func reorderList(head *ListNode) {
	if head == nil || head.Next == nil {
		return
	}
	// ① 快慢指针找中点，slow 停在前半段最后一个节点
	slow, fast := head, head
	for fast.Next != nil && fast.Next.Next != nil {
		slow = slow.Next
		fast = fast.Next.Next
	}
	// ② 反转后半段，并把前半段断开
	second := slow.Next
	slow.Next = nil // 断开！前半段到此为止
	var prev *ListNode
	for second != nil {
		next := second.Next
		second.Next = prev
		prev = second
		second = next
	}
	// ③ 交错合并：p1 走前半，p2 走反转后的后半
	p1, p2 := head, prev
	for p2 != nil {
		n1, n2 := p1.Next, p2.Next // 先存后手，改完指针就找不回了
		p1.Next = p2
		p2.Next = n1
		p1, p2 = n1, n2
	}
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- `slow.Next = nil` 断开前半段，忘了这步合并时乱成一锅粥
- 合并时必须先存 `p1.Next`/`p2.Next` 再改指针，顺序一反就丢链子
- 第二段 ≤ 第一段，循环以 `p2 != nil` 为准

### 🎤 口述模板

> "重排 = 后半段反转后拉链合并，三步：快慢指针找中点断开；反转后半段；两指针从两条链出发交错连接，每次先存后手再改指针。O(n) 时间 O(1) 空间。"

## 7｜LC138 随机链表的复制（中等）⭐

**题干**：链表节点除 `Next` 外还有 `Random` 指针，可指向链表任意节点或 `nil`。要求**深拷贝**整条链表（新链表不得引用原链表节点）。
### 解题思路：难在 Random 指向"还没出生"的节点

只有 Next 的话一遍扫着复制就完事；但 Random 可能指向后面还没复制出来的节点——**先办户口，再拉关系**。

- **哈希法**：第一遍把所有旧节点复制出来登记 `旧节点 → 新节点` 的 map，第二遍接 Next，第三遍接 Random，查关系一查一个准。
- **原地交错插入法**：把新节点直接插在对应旧节点后面（`A → A' → B → B'`），则 `A'.Random = A.Random.Next`——旧节点 random 指向谁，谁的"下一个"就是它的复制，O(1) 空间拿到关系。

```text
交错插入后:  A → A' → B → B' → C → C'
A.Random = C  ⇒  A'.Random = C.Next = C'
```

| 维度       | 哈希法         | 原地交错插入法      |
|------------|----------------|---------------------|
| 时间       | O(n)           | O(n)                |
| 空间       | O(n)（map）    | O(1)（不算输出）    |
| 是否动原链 | 不动           | 临时改动，最后还原  |
| 面试建议   | **先写它，稳** | 追问 O(1) 空间再上  |

### 代码（哈希法，三次遍历）

```go
package main

func copyRandomList(head *Node) *Node {
	if head == nil {
		return nil
	}
	// 第一遍：为每个旧节点造一个新节点，登记到“户口本” map
	m := make(map[*Node]*Node)
	for p := head; p != nil; p = p.Next {
		m[p] = &Node{Val: p.Val}
	}
	// 第二遍：接 Next（map 查不到的 key 返回零值 nil，和原链的 nil 正好对上）
	for p := head; p != nil; p = p.Next {
		m[p].Next = m[p.Next]
	}
	// 第三遍：接 Random
	for p := head; p != nil; p = p.Next {
		m[p].Random = m[p.Random]
	}
	return m[head]
}
```

### 代码（原地交错插入法）

```go
package main

func copyRandomListInterleaved(head *Node) *Node {
	if head == nil {
		return nil
	}
	// ① 每个旧节点后面插入它的复制：A → A' → B → B' → C → C'
	for p := head; p != nil; {
		next := p.Next
		p.Next = &Node{Val: p.Val, Next: next}
		p = next
	}
	// ② 复制节点的 Random = 旧节点 Random 的“下一个”（即那个节点的复制）
	for p := head; p != nil; p = p.Next.Next {
		if p.Random != nil {
			p.Next.Random = p.Random.Next
		}
	}
	// ③ 把交错的两条链拆开，同时把原链恢复原状
	dummy := &Node{}
	tail := dummy
	for p := head; p != nil; {
		tail.Next = p.Next   // 摘下复制节点
		tail = tail.Next
		p.Next = p.Next.Next // 原链恢复原状
		p = p.Next
	}
	return dummy.Next
}
```

### 易错点

- 哈希法 map 以**旧节点指针**为 key；`m[p.Next]` 在 `p.Next == nil` 时返回 nil，不用特判（Go map 查不到返回零值）
- 交错法第 ③ 步必须**边拆边还原原链**，原链被改坏是常见挂点
- 深拷贝 ≠ 拷指针：新链表任何指针都不能指向旧节点

### 🎤 口述模板

> "难点是 Random 可能指向还没复制出来的节点。哈希法：先把所有节点复制进 旧→新 的 map，再三遍分别登记、接 Next、接 Random，O(n) 时间 O(n) 空间。要 O(1) 空间就用交错插入：新节点插到旧节点后面，新节点的 random 就是旧节点 random 的 next，最后拆链并还原原链表。"

## 8｜LC21 合并两个有序链表（简单）

**题干**：将两个升序链表合并为一个新的升序链表并返回，新链表由拼接给定链表的所有节点组成。
### 解题思路：归并排序的 merge 搬家

归并排序 merge 环节的链表版：双指针各指一条链，**谁小接谁**。唯一的烦人事是"结果的头是谁"——**哑节点（dummy）**占住头的位置，尾插法一路接下去，特判消失。哑节点是链表第一大套路：**凡是头节点可能变（合并/删头/拼接），先想哑节点**。

```text
list1: 1 → 2 → 4    list2: 1 → 3 → 4
tail 从 dummy 出发谁小接谁:  dummy → 1 → 1 → 2 → 3 → 4 → 4
```

```go
package main

func mergeTwoLists(list1, list2 *ListNode) *ListNode {
	dummy := &ListNode{} // 哑节点：占住“头”的位置，免去特判
	tail := dummy
	for list1 != nil && list2 != nil {
		if list1.Val <= list2.Val { // 谁小接谁
			tail.Next = list1
			list1 = list1.Next
		} else {
			tail.Next = list2
			list2 = list2.Next
		}
		tail = tail.Next
	}
	// 走完必剩一条（或都空），整段接上，不用逐个搬
	if list1 != nil {
		tail.Next = list1
	} else {
		tail.Next = list2
	}
	return dummy.Next
}
```

**复杂度**：时间 O(m+n)｜空间 O(1)

### 易错点

- 循环条件是 `&&`（两条都非空才比），出来后剩下的整段直接挂 `tail.Next`
- 忘了 `tail = tail.Next` 尾指针不前进，死循环
- 题目要求**拼接原节点**，别 new 一堆新节点（那成了构造新链表）

### 🎤 口述模板

> "归并 merge 的链表版：哑节点占头，双指针谁小接谁、尾插前进，最后剩下的整段接上。O(m+n) 时间 O(1) 空间。哑节点把'头是谁'的特判干掉，是合并类题的通用起手式。"

## 9｜LC2 两数相加（中等）

**题干**：两个非负整数按**逆序**存在两条链表里（342 存成 `2 → 4 → 3`），每位一个节点。相加返回同样逆序的链表。
### 解题思路：小学竖式加法

逆序存储是天赐的好设计：**头节点就是个位**，从头加就是从个位加，顺着走就是进位方向。`sum = 两位之和 + 进位`，写 `sum % 10`，进 `sum / 10`。

```text
l1 = 2 → 4 → 3 (342)   l2 = 5 → 6 → 4 (465)
位 1: 2+5   = 7  → 写 7 进 0
位 2: 4+6+0 = 10 → 写 0 进 1
位 3: 3+4+1 = 8  → 写 8 进 0
结果: 7 → 0 → 8 (807) ✓
```

```go
package main

func addTwoNumbers(l1, l2 *ListNode) *ListNode {
	dummy := &ListNode{}
	tail := dummy
	carry := 0
	// 循环条件把“两条链走完”和“最后还有进位”合并处理，收尾不用补节点
	for l1 != nil || l2 != nil || carry != 0 {
		sum := carry
		if l1 != nil {
			sum += l1.Val
			l1 = l1.Next
		}
		if l2 != nil {
			sum += l2.Val
			l2 = l2.Next
		}
		carry = sum / 10                   // 新进位
		tail.Next = &ListNode{Val: sum % 10} // 当前位，新建节点
		tail = tail.Next
	}
	return dummy.Next
}
```

**复杂度**：时间 O(max(m,n))｜空间 O(1)（不算返回链表）

### 易错点

- 最高位进位（`99 + 1` 类）最后要多一个节点：把 `carry != 0` 写进循环条件，一劳永逸
- 两条链长度不同：短的那边按 0 参与，`if l1 != nil` 别写成数组思维
- 先算 `sum` 再拆 `sum/10`、`sum%10`，别边加边进位把自己绕晕

### 🎤 口述模板

> "逆序存储意味着头就是个位，直接模拟竖式加法：逐位求和带进位，写 sum mod 10、进 sum div 10。循环条件是'两链未走完或还有进位'，最高位进位的收尾也吃进主循环。O(max(m,n)) 时间。"

## 10｜LC19 删除链表的倒数第 N 个结点（中等）

**题干**：给你头节点 `head` 和整数 `n`，删除倒数第 `n` 个节点并返回头节点。要求**一趟扫描**。
### 解题思路：让快慢指针隔着 N 步

倒数第 n 个 = 正数第 len-n+1 个，先数长度是两遍扫描。一遍扫描：**快指针先冲 n+1 步**拉开 n+1 的间隔，再快慢同速前进——fast 到 `nil` 时 slow 恰好停在**被删节点的前一个**（删节点必须知道前驱，这就是 n+1 而不是 n 的原因）。删除类操作配哑节点兜底：被删的可能是头节点。

```text
dummy → 1 → 2 → 3 → 4 → 5     n = 2
① fast 从 dummy 先走 n+1 = 3 步:  slow=dummy  fast=3
② 同速前进到 fast=nil:           slow=3      fast=nil
③ 摘掉 slow.Next(4):             dummy → 1 → 2 → 3 → 5 ✓
```

```go
package main

func removeNthFromEnd(head *ListNode, n int) *ListNode {
	dummy := &ListNode{Next: head} // 被删的可能是头节点，哑节点兜底
	fast := dummy
	// ① fast 先走 n+1 步，和 slow 拉开 n+1 的间隔
	for i := 0; i <= n; i++ {
		fast = fast.Next
	}
	// ② 同速前进，fast 到 nil 时 slow 停在被删节点的前一个
	slow := dummy
	for fast != nil {
		fast = fast.Next
		slow = slow.Next
	}
	// ③ 摘掉 slow.Next（倒数第 n 个）
	slow.Next = slow.Next.Next
	return dummy.Next
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- fast 走 **n+1** 步（从 dummy 出发）：走 n 步的话 slow 停在被删节点本体上，没法删自己
- 必须哑节点：删头节点（n = 链表长度）时没有前驱
- 本题保证 `1 ≤ n ≤ 长度`，`slow.Next.Next` 不会空指针；条件放宽就要先校验

### 🎤 口述模板

> "一遍扫描：快指针从哑节点先走 n+1 步，和慢指针锁定 n+1 间隔；同速前进，fast 到 nil 时 slow 正好停在被删节点的前驱，摘掉 slow.Next。哑节点兜住删头的情况。O(n) 时间 O(1) 空间。"

## 11｜LC82 删除排序链表中的重复元素 II（中等）

**题干**：升序链表中出现重复的元素**全部删掉**，只保留没有重复出现的数字。（对比 LC83：重复的留一个。）
### 解题思路：整段跳过，prev 不冲锋

排序链表的重复值必然**挨在一起**，所以是"重复段整段删除"。难点是头节点可能整段被删——哑节点解决。维护 `prev` 指向"已确认无重复"的尾节点，看 `prev.Next` 和 `prev.Next.Next`：同值就把这**一整段**全部跳过，且 **prev 不动**（新接上来的可能和后面继续重复，交给下一轮）；不同值 prev 才前进。

```text
dummy → 1 → 2 → 3 → 3 → 4 → 4 → 5
prev=1: 2≠3 正常推进 prev=2
prev=2: 3==3 整段跳过、4==4 整段跳过 → dummy → 1 → 2 → 5 ✓
```

```go
package main

func deleteDuplicates(head *ListNode) *ListNode {
	dummy := &ListNode{Next: head} // 头部可能整段被删，必须哑节点
	prev := dummy                  // prev 永远指向“已确认无重复”的尾节点
	for prev.Next != nil && prev.Next.Next != nil {
		if prev.Next.Val == prev.Next.Next.Val {
			// 发现重复段：值等于 dupVal 的全部跳过，一个不留
			dupVal := prev.Next.Val
			for prev.Next != nil && prev.Next.Val == dupVal {
				prev.Next = prev.Next.Next
			}
			// prev 本身不动！新接上来的节点可能和后面继续重复
		} else {
			prev = prev.Next // 不重复才推进
		}
	}
	return dummy.Next
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- 和 LC83 区分：83 是"重复的留一个"（只跳一个），82 是"见重复全删"（整段跳过）
- **跳过整段后 prev 不能动**：新接上来的节点可能继续重复（如 `1→1→2→2`），交给下一轮判断
- 比较的永远是 `prev.Next` 和 `prev.Next.Next`，别拿 prev 本人的值比——prev 可能是哑节点

### 🎤 口述模板

> "排序链表重复值必相邻，策略是整段跳过。哑节点兜住'头就重复'；prev 始终指向已确认无重复的尾，发现 prev.Next 与再后一个同值，就把该值整段摘掉，期间 prev 不前进，防连续重复段。一遍 O(n)。"

## 12｜LC61 旋转链表（中等）

**题干**：给你头节点 `head` 和整数 `k`，将链表每个节点向右移动 `k` 位。如 `1→2→3→4→5, k=2` 变 `4→5→1→2→3`。
### 解题思路：转 k 圈不如"一刀切"

模拟"每次把尾搬到头"是 O(n·k)，pass。换视角：右旋 k 次 = **把倒数 k 个整体搬到前面** = 在倒数第 k+1 个节点（新尾）处切一刀。两个细节：`k` 可能远大于长度，先 `k %= n`；倒数第 k+1 个不好直接拿——把链表**首尾接成环**，从头走 `n-k-1` 步就是新尾，再断开。

```text
1 → 2 → 3 → 4 → 5,  k = 2   (n = 5, k % n = 2)
① 首尾相连成环:  1 → 2 → 3 → 4 → 5 ─┐
                  ↑_________________┘
② 从头走 n-k-1 = 2 步到新尾 3, 新头是 4
③ 3.Next = nil 断环:  4 → 5 → 1 → 2 → 3 ✓
```

```go
package main

func rotateRight(head *ListNode, k int) *ListNode {
	if head == nil || head.Next == nil || k == 0 {
		return head
	}
	// ① 数长度，顺便拿到尾节点
	n := 1
	tail := head
	for tail.Next != nil {
		tail = tail.Next
		n++
	}
	k %= n // k 可能远大于长度，先取模
	if k == 0 {
		return head // 正好转整数圈，原样返回
	}
	// ② 首尾相连成环
	tail.Next = head
	// ③ 新尾是倒数第 k+1 个：从头走 n-k-1 步
	newTail := head
	for i := 0; i < n-k-1; i++ {
		newTail = newTail.Next
	}
	newHead := newTail.Next
	newTail.Next = nil // ④ 断环，别忘了
	return newHead
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- `k %= n` 必须做（LeetCode 卡过 k = 2×10⁹ 的用例）；取模后 k==0 直接返回
- 忘了 `newTail.Next = nil`，结果是环形链表，判题直接挂
- 成环后走 `n-k-1` 步到新尾——建议拿 `1→2→3→4→5, k=2` 手推一遍再背；空链表/单节点靠开头的卫语句兜底

### 🎤 口述模板

> "右旋 k 次等价于把倒数 k 个整体搬到前面。先数长度拿尾节点，k 对长度取模；首尾接成环，从头走 n-k-1 步找到新尾，断开环，新尾的下一个就是新头。O(n) 时间 O(1) 空间。"

## 13｜LC86 分隔链表（中等）

**题干**：给你头节点 `head` 和值 `x`，分隔链表使**所有小于 x 的节点都排在大于等于 x 的节点前面**，且**保持每个节点原有相对顺序**。
### 解题思路：小的串一条，大的串一条，最后接上

"保持相对顺序"意味着只能尾插（头插会逆序）。开两条链：`small` 收 `< x`，`large` 收 `>= x`，各配一个哑节点带头，扫一遍原链把节点摘下来挂到对应链尾，最后 small 尾接 large 头。"两条哑节点链再拼接"是链表分区/快排链表化的通用套路（LC328 奇偶链表同款）。

```text
原: 1 → 4 → 3 → 2 → 5 → 2,  x = 3
small: sDummy → 1 → 2 → 2      large: lDummy → 4 → 3 → 5
拼接:  sDummy → 1 → 2 → 2 → 4 → 3 → 5 ✓
```

```go
package main

func partition(head *ListNode, x int) *ListNode {
	smallDummy := &ListNode{} // 收“小于 x”的链
	largeDummy := &ListNode{} // 收“大于等于 x”的链
	small, large := smallDummy, largeDummy
	for p := head; p != nil; {
		next := p.Next
		p.Next = nil // 先把节点摘干净，别拖着原链的后半串
		if p.Val < x {
			small.Next = p
			small = small.Next
		} else {
			large.Next = p
			large = large.Next
		}
		p = next
	}
	small.Next = largeDummy.Next // 两条链首尾相接
	return smallDummy.Next
}
```

**复杂度**：时间 O(n)｜空间 O(1)

### 易错点

- 摘节点时 `p.Next = nil` 断干净：显式断开是好习惯，快排链表化时不断必挂
- 保持相对顺序 → 只能**尾插**，两条链各维护自己的尾指针
- 返回 `smallDummy.Next`；拼接方向是 small 尾 → large 头，别接反

### 🎤 口述模板

> "两个哑节点各带一条链：小的尾插进 small 链，其余尾插进 large 链，节点先摘干净再挂；扫完把 small 的尾接上 large 的头。尾插保证相对顺序，哑节点免掉空链和头节点特判。O(n) 时间 O(1) 空间。"

## 14｜LC146 LRU 缓存（中等）⭐⭐ 后端超高频

**题干**：设计 LRU 缓存：`Constructor(capacity)` 初始化；`Get(key)` 存在则返回值并记为"最近使用"，不存在返回 -1；`Put(key, value)` 存在则更新并记为最近使用，不存在则插入——**容量满时淘汰最久未使用的 key**。要求 Get/Put 均 O(1)。
### 解题思路：为什么偏偏是"哈希 + 双向链表"

一步步逼出来：

1. **为什么哈希表？** Get 要 O(1) 定位 key，只有哈希表做得到。但哈希表无序，"谁最久没用"它不知道。
2. **为什么还要链表？** "新旧程度"是**随时在变的顺序**：每次访问都要把节点挪到"最新"端，淘汰时从"最旧"端拿一个。链表 O(1) 摘除 + O(1) 插头，正合适。
3. **为什么双向而不是单向？** 摘除节点要改它**前驱**的指针。单向链表找前驱要 O(n) 从头扫；双向链表节点自带 `Prev`，O(1) 直达前驱。这一问几乎必考。

最终形态：**哈希表存 key → 链表节点（定位），双向链表维护新旧顺序（调度）**，新在头、旧在尾，两头哑节点占位。

```text
双向链表摘除 cur（O(1)，不用找前驱）：
   ... ⇄ prev ⇄ cur ⇄ next ⇄ ...
        prev.Next = next、next.Prev = prev    （前后指针互相跨过 cur）
头插 node（O(1)）：插到哑头和第一个真节点之间 → head ⇄ node ⇄ oldFirst
整条链（哑头哑尾永不删除）：head ⇄ [最新] ⇄ ... ⇄ [最旧] ⇄ tail
```

| 操作 | key 存在           | key 不存在                      |
|------|--------------------|---------------------------------|
| Get  | 摘除→头插，返回 val | 返回 -1                         |
| Put  | 更新 val，摘除→头插 | 满→先淘汰 tail.Prev；再新建头插 |

**呼应 Redis**（后端面试加分点）：Redis 的 `allkeys-lru` 并没有给每个 key 维护真的双向链表——每个键值对多挂两个指针，亿级 key 场景下内存吃不消。Redis 用的是**近似 LRU**：随机采样 `maxmemory-samples` 个 key（默认 5），淘汰其中最久未访问的；Redis 3.0 又加了候选池（pool）优化，让近似 LRU 逼近理论 LRU。从"手写 LRU"聊到"Redis 为什么不这么干"，才是后端该有的纵深。

```go
package main

// 双向链表节点：key 必须存！淘汰时要反过来从 map 删，没有 key 就删不成
type dListNode struct {
	key, val   int
	Prev, Next *dListNode
}

type LRUCache struct {
	capacity int
	m        map[int]*dListNode // key → 链表节点，O(1) 定位
	head     *dListNode         // 哑头：head.Next 永远是“最新”
	tail     *dListNode         // 哑尾：tail.Prev 永远是“最旧”
}

func Constructor(capacity int) LRUCache {
	head, tail := &dListNode{}, &dListNode{}
	head.Next = tail
	tail.Prev = head // 先让哑头哑尾手拉手，之后永不分离
	return LRUCache{
		capacity: capacity,
		m:        make(map[int]*dListNode, capacity),
		head:     head,
		tail:     tail,
	}
}

func (c *LRUCache) Get(key int) int {
	node, ok := c.m[key]
	if !ok {
		return -1
	}
	c.moveToFront(node) // 访问过 = 变“新”，挪到队头
	return node.val
}

func (c *LRUCache) Put(key int, value int) {
	if node, ok := c.m[key]; ok { // 已存在：更新值 + 变新，不触发淘汰
		node.val = value
		c.moveToFront(node)
		return
	}
	if len(c.m) >= c.capacity { // 满了：先淘汰最旧
		oldest := c.tail.Prev
		c.remove(oldest)
		delete(c.m, oldest.key) // 节点存 key 就是为了这一刻
	}
	node := &dListNode{key: key, val: value}
	c.m[key] = node
	c.addToFront(node)
}

// 头插：接在哑头后面
func (c *LRUCache) addToFront(node *dListNode) {
	node.Prev = c.head
	node.Next = c.head.Next
	c.head.Next.Prev = node
	c.head.Next = node
}

// 摘除：前后指针互相跨过自己即可，O(1)，这就是选双向链表的原因
func (c *LRUCache) remove(node *dListNode) {
	node.Prev.Next = node.Next
	node.Next.Prev = node.Prev
}

func (c *LRUCache) moveToFront(node *dListNode) {
	c.remove(node)
	c.addToFront(node)
}
```

| 操作 | 时间 | 空间               |
|------|------|--------------------|
| Get  | O(1) | O(capacity)（整体） |
| Put  | O(1) | —                  |

### 易错点

- **节点必须存 key**：淘汰尾节点时要 `delete(map, key)`，只存 val 就抓瞎——全网最经典翻车点
- Put 已存在的 key 是"更新"，**不占新容量、不触发淘汰**
- 淘汰的是 `tail.Prev`（最旧），头插在 `head.Next`（最新），方向别搞反
- 哑头 + 哑尾让链表**永远不为空**，空指针特判全部消失
- Go 接收者：要改 `c.m`、`c.head`，必须用指针接收者 `(c *LRUCache)`

### 🎤 口述模板

> "Get/Put 都 O(1)：哈希表 O(1) 定位 key，双向链表维护新旧顺序——摘除和头插都 O(1)，双向是因为删节点需要前驱，单向找前驱 O(n)。头放最新、尾放最旧，两头挂哑节点消灭边界。Get 命中搬到头；Put 命中更新搬头，未命中且满就先摘尾前驱并同步删 map 再头插。经典细节：节点必须存 key，不然淘汰时没法从哈希表删。Redis 为了省内存用的是采样式近似 LRU，不是真 LRU。"
