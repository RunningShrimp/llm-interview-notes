## 先立模板：左闭右闭，循环内判等

二分写法百花齐放，背一套就够——**左闭右闭 `[left, right]`**：

```go
package main

import "fmt"

// 左闭右闭标准模板：区间 [left, right] 内二分查找 target
func binarySearch(nums []int, target int) int {
	left, right := 0, len(nums)-1
	for left <= right { // 区间非空才继续
		mid := left + (right-left)/2 // 防溢出写法
		if nums[mid] == target {
			return mid // 找到直接返回
		} else if nums[mid] < target {
			left = mid + 1 // 目标在右半，[mid] 已排除
		} else {
			right = mid - 1 // 目标在左半，[mid] 已排除
		}
	}
	return -1 // 区间空了 = 没有目标
}

func main() {
	fmt.Println(binarySearch([]int{1, 3, 5, 6, 8}, 5) == 2)  // true
	fmt.Println(binarySearch([]int{1, 3, 5, 6, 8}, 7) == -1) // true
}
```

为什么推这套：`left <= right` 与 `right = mid - 1` 语义自洽（mid 永远被检查过并排除），不会陷入"到底该 `<` 还是 `<=`、`mid` 还是 `mid±1`"的记忆泥潭。后文所有变体（找边界、旋转数组、分割线）都从这套出发改。

## 一、LC35 搜索插入位置（简单）

### 题干简述

升序数组 + 目标值，找到就返回下标；找不到返回**它按顺序插入的位置**。`[1,3,5,6]`，5→2；2→1；7→4。要求 O(log n)。

### 解题思路：标准模板，失败点就是插入点

模板跑完没找到时 `left` 停在哪？**停在"第一个 ≥ target 的位置"**——恰好就是插入位置。

```
[1, 3, 5, 6]  target=2
 l=0 r=3 mid=1  nums[1]=3 > 2 → r=0
 l=0 r=0 mid=0  nums[0]=1 < 2 → l=1
 l=1 > r=0 退出 → 返回 left=1 ✓（插到 1 和 3 之间）

直觉：left 一路向右赶，永远指向"还没被证明太小"的第一个位置。
所有 < target 的都被 left 越过去了，剩下的都 ≥ target。
```

本题也是"找左边界"的雏形——把"返回 -1"换成"返回 left"，二分就从"查找"变成了"定位"。

### 完整可编译代码

```go
package main

import "fmt"

func searchInsert(nums []int, target int) int {
	left, right := 0, len(nums)-1
	for left <= right {
		mid := left + (right-left)/2
		if nums[mid] == target {
			return mid // 找到直接回
		} else if nums[mid] < target {
			left = mid + 1 // 太小，目标在右
		} else {
			right = mid - 1 // 太大，目标在左
		}
	}
	return left // 退出时 left = 第一个 ≥ target 的位置 = 插入点
}

func main() {
	fmt.Println(searchInsert([]int{1, 3, 5, 6}, 5) == 2) // true
	fmt.Println(searchInsert([]int{1, 3, 5, 6}, 2) == 1) // true
	fmt.Println(searchInsert([]int{1, 3, 5, 6}, 7) == 4) // true
	fmt.Println(searchInsert([]int{1, 3, 5, 6}, 0) == 0) // true
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(log n) |
| 空间 | O(1) |

### 易错点

1. 循环外返回 `-1` 是查找语义；本题要返回 `left`（插入语义），别照抄模板尾巴。
2. `mid := (left+right)/2` 在某些语言大数组会溢出；Go int 64 位没事，但写成 `left+(right-left)/2` 是通用好习惯。

### 🎤 口述模板

> "标准左闭右闭二分，找到返回下标；找不到时 left 正好停在第一个大于等于 target 的位置，就是插入点。O(log n)。这题本质是'找左边界'的入门形态。"

## 二、LC74 搜索二维矩阵（中等）

### 题干简述

每行升序，且**每行第一个数 > 上一行最后一个数**——整个矩阵展平就是一条升序数组。判断 target 是否在矩阵中。O(log(m·n))。

### 解题思路：坐标一维化，一次二分打穿

矩阵既然"逐行接力升序"，就把 `(row, col)` 映射成一维下标 `k`：

```
matrix = [[1, 3, 5, 7],
          [10,11,16,20],
          [23,30,34,60]]   m=3 行 n=4 列

一维 k → 二维:  row = k / n ,  col = k % n
  k=0..3 第一行, k=4..7 第二行, k=8..11 第三行

[1,3,5,7,10,11,16,20,23,30,34,60]  ← 眼里只有这条升序数组
直接套 LC35 模板，访问时做个坐标换算即可。
```

为什么不能"先二分行再二分列"？——也可以（两次 log），但一次二分更简洁，且面试官想听的就是**"识别出可二分的单调结构"**这个抽象能力。

### 完整可编译代码

```go
package main

import "fmt"

func searchMatrix(matrix [][]int, target int) bool {
	m, n := len(matrix), len(matrix[0])
	left, right := 0, m*n-1 // 一维化区间
	for left <= right {
		mid := left + (right-left)/2
		v := matrix[mid/n][mid%n] // 坐标换算
		if v == target {
			return true
		} else if v < target {
			left = mid + 1
		} else {
			right = mid - 1
		}
	}
	return false
}

func main() {
	m := [][]int{{1, 3, 5, 7}, {10, 11, 16, 20}, {23, 30, 34, 60}}
	fmt.Println(searchMatrix(m, 3) == true)  // true
	fmt.Println(searchMatrix(m, 13) == false) // true
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(log(m·n)) |
| 空间 | O(1) |

### 易错点

1. 本题前提是"行间也接力升序"；如果只保证每行升序、行间不保证（LC240 搜索二维矩阵 II），一维化失效，得用"右上角出发的排除法"——两题常连考，主动说区别是加分项。
2. 坐标换算 `mid/n`、`mid%n` 别写反（n 是列数）。

### 🎤 口述模板

> "行内升序且行间接力，说明矩阵逻辑上就是一条升序数组。把下标一维化，k 除以列数得行、取余得列，套标准二分，一次 O(log mn) 打穿。如果行间不接力就是 LC240，改用右上角排除法，这两题我会主动区分。"

## 三、LC34 查找元素的第一个和最后一个位置（中等）

### 题干简述

非递减数组找 target 的**开始位置和结束位置**，没有返回 `[-1,-1]`。要求 O(log n)。`[5,7,7,8,8,10]`，8→`[3,4]`。

### 解题思路：不找"它"，找"它的左邻断层"

模板找到 mid 就返回——但这里有一串 8，必须**找到边界**。诀窍：**永远不因相等而停**，把相等也往一边压：

```
找左边界（第一个 = target 的位置）：
  nums[mid] < target → 左边全太小，left = mid+1
  nums[mid] >= target → mid 可能就是答案，但左边可能还有，
                        right = mid-1（mid 并没被丢弃，答案记在 left 里）

[5, 7, 7, 8, 8, 10]  target=8   找左边界
 l=0 r=5 mid=2  7 < 8  → l=3
 l=3 r=5 mid=4  8 >= 8 → r=3     （不返回！继续往左压）
 l=3 r=3 mid=3  8 >= 8 → r=2
 l=3 > r=2 退出 → left=3 = 第一个 8 ✓

找右边界对称：nums[mid] <= target → left=mid+1；
退出后 left = 第一个 > target 的位置，右边界 = left-1。
```

**统一理解**：找左边界 = LC35 的"插入位置"精确版——left 永远收敛到"第一个满足条件的位置"。右边界 = "第一个 > target 的位置" − 1。两次二分，条件一个 `>=` 一个 `>`。

### 完整可编译代码

```go
package main

import "fmt"

// lowerBound 返回第一个 >= target 的下标（找不到返回 n）
func lowerBound(nums []int, target int) int {
	left, right := 0, len(nums)-1
	for left <= right {
		mid := left + (right-left)/2
		if nums[mid] < target {
			left = mid + 1 // 严格小于才右移：相等也往左压
		} else {
			right = mid - 1
		}
	}
	return left
}

func searchRange(nums []int, target int) []int {
	start := lowerBound(nums, target) // 第一个 >= target
	if start == len(nums) || nums[start] != target {
		return []int{-1, -1} // 根本不存在
	}
	end := lowerBound(nums, target+1) - 1 // 第一个 >= target+1 再减一 = 最后一个 target
	return []int{start, end}
}

func main() {
	r1 := searchRange([]int{5, 7, 7, 8, 8, 10}, 8)
	fmt.Println(r1[0] == 3 && r1[1] == 4)              // true
	r2 := searchRange([]int{5, 7, 7, 8, 8, 10}, 6)
	fmt.Println(r2[0] == -1 && r2[1] == -1)            // true
	r3 := searchRange([]int{}, 0)
	fmt.Println(r3[0] == -1 && r3[1] == -1)            // true
}
```

`lowerBound` 是个**万金轮**：LC35 插入位置、本题双边界、LC69 x的平方根、LC875 爱吃香蕉的珂珂全是它变体。面试时把它抽成函数并说出名字（lower_bound / bisect_left），直接体现素养。

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(log n)（两次二分） |
| 空间 | O(1) |

### 易错点

1. 判存在必须查 `nums[start] != target`——lowerBound 只保证"第一个 ≥"，不保证相等。
2. 右边界用 `lowerBound(target+1) - 1` 而不是另写一套对称逻辑，**一套函数复用两次**，边界 bug 直接减半（注意 target+1 不会溢出：题目值域 ±10⁹）。
3. 空数组：`start == len(nums)` 先挡，否则 `nums[start]` 越界 panic。

### 🎤 口述模板

> "核心是一个 lowerBound 函数：找第一个大于等于 target 的位置，相等也不停、继续往左压。开始位置就是 lowerBound(target)；结束位置是 lowerBound(target+1) 减一——第一个比 target 大的位置再退一步。两次二分 O(log n)，这个函数还能通吃插入位置、x平方根一族题。"

## 四、LC33 搜索旋转排序数组（中等）

### 题干简述

升序数组在未知点旋转过（如 `[0,1,2,4,5,6,7]` → `[4,5,6,7,0,1,2]`），元素互不相同。找 target 下标，O(log n)。

### 解题思路：断成两截，每截内部仍有序——"判哪半有序"

旋转数组不是全局有序，但**从中点切开，至少有一半是纯升序的**。判断 target 是否落在这有序的一半里：在 → 普通二分；不在 → 去另一半。

```
[4, 5, 6, 7, 0, 1, 2]  target=0
 l=0 r=6 mid=3
 nums[l]=4 <= nums[mid]=7 → 左半 [4,5,6,7] 有序
   target=0 在 [4,7] 里吗？ 4<=0<=7? 否 → 去右半 l=mid+1=4

 l=4 r=6 mid=5
 nums[l]=0 <= nums[mid]=1 → 左半 [0,1] 有序
   0<=0<=1? 是 → r=mid-1=4

 l=4 r=4 mid=4  nums[4]=0 == target ✓ 返回 4

判断框架（背这两行）：
  nums[left] <= nums[mid]      → 左半有序
  有序的一半里 nums[left]<=t<nums[mid+1] 边界夹一下 → 在/不在
```

为什么 `<=` 而不是 `<`：区间缩到只剩一两个元素时 `left == mid`，必须算"左半有序"，否则两边都不是、逻辑死角。

### 完整可编译代码

```go
package main

import "fmt"

func search(nums []int, target int) int {
	left, right := 0, len(nums)-1
	for left <= right {
		mid := left + (right-left)/2
		if nums[mid] == target {
			return mid
		}
		if nums[left] <= nums[mid] { // 左半 [left..mid] 有序
			if nums[left] <= target && target < nums[mid] {
				right = mid - 1 // target 夹在有序左半内
			} else {
				left = mid + 1 // 去乱的一半找
			}
		} else { // 右半 [mid..right] 有序
			if nums[mid] < target && target <= nums[right] {
				left = mid + 1
			} else {
				right = mid - 1
			}
		}
	}
	return -1
}

func main() {
	fmt.Println(search([]int{4, 5, 6, 7, 0, 1, 2}, 0) == 4)  // true
	fmt.Println(search([]int{4, 5, 6, 7, 0, 1, 2}, 3) == -1) // true
	fmt.Println(search([]int{1}, 1) == 0)                    // true
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(log n)（每次仍砍一半） |
| 空间 | O(1) |

### 易错点

1. "哪半有序"用 `nums[left] <= nums[mid]` 判，**等号必须有**（单元素半边场景）。
2. "target 在有序半边吗"的夹逼：左半有序时是 `nums[left] <= target && target < nums[mid]`——注意 mid 已判等排除，右边是严格 `<`。
3. 数组有重复元素时（LC81）此法退化，需要 `left++` 逐个啃——面试常追问，知道区别即可。

### 🎤 口述模板

> "旋转数组从中点切开后必有一半是纯升序的。先用 nums[left] 和 nums[mid] 比较判断哪半有序，再用边界值夹逼判断 target 在不在这有序的一半里：在就普通二分收进去，不在就去乱的另一半。每轮仍砍一半，O(log n)。有重复元素的变体 LC81 我也知道要退化成线性啃。"

## 五、LC153 寻找旋转排序数组中的最小值（中等）

### 题干简述

元素互不相同的升序数组旋转过，找**最小值**。`[4,5,6,7,0,1,2] → 0`。O(log n)。

### 解题思路：和右端点比，"我比右端大说明我在断崖左边"

最小值在"断崖"处：旋转把 `[min...max]` 断成 `[大段, 小段]`。中点跟**右端点**比：

```
[4, 5, 6, 7, 0, 1, 2]        r 指着 2
 nums[mid] > nums[right] → mid 在大段，最小值必在 mid 右边 → left = mid+1
 nums[mid] < nums[right] → mid 已在小段，mid 本身可能就是最小 → right = mid

 l=0 r=6 mid=3  7 > 2 → l=4
 l=4 r=6 mid=5  1 < 2 → r=5
 l=4 r=5 mid=4  0 < 1 → r=4
 l==r==4  nums[4]=0 ✓
```

两个关键区别于 LC33：

1. **比右端点，不比左端点**。比左端点无法区分"完全有序"和"断崖在右"（如 `[1,2,3]` vs `[3,1,2]`，mid 都 ≥ left），信息量不足；右端点则天然是"小段的尾巴"，一次比较就知道自己在哪段。
2. `nums[mid] < nums[right]` 时 **right = mid 而非 mid−1**——mid 可能正是答案，不能丢。区间收敛成"左闭右闭但 right 不跨过 mid"，循环条件用 `left < right`，退出时 left 即最小。

### 完整可编译代码

```go
package main

import "fmt"

func findMin(nums []int) int {
	left, right := 0, len(nums)-1
	for left < right { // 收敛到单点
		mid := left + (right-left)/2
		if nums[mid] > nums[right] {
			left = mid + 1 // mid 在大段，最小在右侧
		} else {
			right = mid // mid 在小段，mid 可能就是最小
		}
	}
	return nums[left]
}

func main() {
	fmt.Println(findMin([]int{4, 5, 6, 7, 0, 1, 2}) == 0) // true
	fmt.Println(findMin([]int{3, 4, 5, 1, 2}) == 1)      // true
	fmt.Println(findMin([]int{11, 13, 15, 17}) == 11)    // true（没旋转）
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(log n) |
| 空间 | O(1) |

### 易错点

1. 循环条件 `left < right`（不是 `<=`）：right=mid 的写法下 `left==right` 即收敛，写 `<=` 会死循环。
2. 有重复元素版（LC154）会出现 `nums[mid]==nums[right]` 无法判段，只能 `right--` 逐步缩，最坏 O(n)——追问高频。
3. 数组没旋转时（完全有序）算法自然走到 left=0，无需特判。

### 🎤 口述模板

> "最小值在断崖处。中点和右端点比：比右端大，说明自己在断崖左边的大段，最小必在右侧 left=mid+1；比右端小，说明自己已在小段，mid 可能就是最小，right=mid 不越过它。收敛到 left==right 即答案，O(log n)。和左端点比区分不了完全有序和断崖在右，所以必须比右端点。重复元素版 LC154 我知道要退化 right--。"

## 六、LC4 寻找两个正序数组的中位数（困难）

### 题干简述

两个升序数组（长度 m、n），找合并后的中位数。要求 O(log(m+n))。`[1,3]` + `[2]` → 2.0。

### 解题思路：不合并，二分"分割线"

中位数的本质：把全部元素切成**个数相等（或左多一个）的两半，且左边全部 ≤ 右边**。不真的合并，而是在**较短的数组**上二分一条"分割线位置 i"，较长数组的分割线 j 由"左半总个数"直接算出来：

```
A = [1, 3, 8, 9]      (m=4，短的那个)
B = [2, 4, 5, 6, 7]   (n=5)

分割线: A 的前 i 个 + B 的前 j 个 = 左半，i + j = (m+n+1)/2
                 ↓i=2            ↓j=3
A:        1   3  |  8   9
B:      2 4 5 | 6  7  ← j = 5-... 直接由总个数算出

合法分割的条件（交叉不越界）：
  A[i-1] <= B[j]   （A 左边最大 ≤ B 右边最小）
  B[j-1] <= A[i]   （B 左边最大 ≤ A 右边最小）

在本例: A[1]=3 <= B[3]=6 ✓  B[2]=5 <= A[2]=8 ✓ 左半 = {1,3,2,4,5}
总数 9（奇）→ 中位数 = max(A[i-1], B[j-1]) = 5
总数偶 → (max左 + min右) / 2

二分什么：i 太小 → A[i-1] > B[j] → i 右移；i 太大 → B[j-1] > A[i] → i 左移。
在 m=4 上二分 → O(log min(m,n)) ✓
```

**为什么要选短数组二分**：j = (m+n+1)/2 − i 由 i 唯一确定，若在长数组上二分，j 可能算出负数或超界，还得钳边界；短数组保证 j 天然合法。

**边界哨兵**：`A[-1]`、`B[-1]` 当 −∞，`A[m]`、`B[n]` 当 +∞——分割线贴边时比较不越界，代码大幅简化。

### 完整可编译代码

```go
package main

import (
	"fmt"
	"math"
)

func findMedianSortedArrays(A, B []int) float64 {
	if len(A) > len(B) { // 保证在短的上面二分
		A, B = B, A
	}
	m, n := len(A), len(B)
	half := (m + n + 1) / 2 // 左半总个数（奇数时左多一个）
	lo, hi := 0, m
	for lo <= hi {
		i := lo + (hi-lo)/2 // A 的分割线：A 左半有 i 个
		j := half - i       // B 的分割线：由总个数直接算
		AL := math.MinInt64 // 哨兵：贴边时当 ±∞
		if i > 0 {
			AL = A[i-1]
		}
		AR := math.MaxInt64
		if i < m {
			AR = A[i]
		}
		BL := math.MinInt64
		if j > 0 {
			BL = B[j-1]
		}
		BR := math.MaxInt64
		if j < n {
			BR = B[j]
		}
		switch {
		case AL <= BR && BL <= AR: // 合法分割，出答案
			if (m+n)%2 == 1 {
				return float64(max(AL, BL)) // 奇数：左半最大
			}
			return float64(max(AL, BL)+min(AR, BR)) / 2 // 偶数：左右取半
		case AL > BR:
			hi = i - 1 // A 出得太多，i 左移
		default:
			lo = i + 1 // B 出得太多（BL>AR），i 右移
		}
	}
	return 0.0 // 按题意不会到这
}

func max(a, b int) int { if a > b { return a }; return b }
func min(a, b int) int { if a < b { return a }; return b }

func main() {
	fmt.Println(findMedianSortedArrays([]int{1, 3}, []int{2}) == 2.0)          // true
	fmt.Println(findMedianSortedArrays([]int{1, 2}, []int{3, 4}) == 2.5)       // true
	fmt.Println(findMedianSortedArrays([]int{1, 3, 8, 9}, []int{2, 4, 5, 6, 7}) == 5) // true
	fmt.Println(findMedianSortedArrays([]int{}, []int{1}) == 1)                // true
}
```

### 复杂度

| 项 | 复杂度 | 说明 |
|----|--------|------|
| 时间 | O(log min(m,n)) | 只在短数组上二分 |
| 空间 | O(1) |

### 易错点

1. `half = (m+n+1)/2` 的 **+1**：总数奇数时让左半多含一个，中位数统一从"左半最大"取，奇偶分支不再纠缠。
2. 哨兵 ±∞ 不能省——`i=0` 或 `i=m` 时 `A[i-1]`、`A[i]` 越界；用哨兵后贴边分割自动合法。
3. 面试允许 O(log(m+n)) 的另一路：**第 k 小数的二分淘汰**（每轮淘汰 k/2 个）。分割线法和第 k 小法都要会一句：短数组二分是 O(log min) 更优。

### 🎤 口述模板

> "中位数等价于一条合法分割线：左半元素个数定死，且左半所有值 ≤ 右半所有值。我在较短的数组上二分它的分割位置 i，长数组的 j 由个数守恒直接算出；交叉比较 A 左 max ≤ B 右 min、B 左 max ≤ A 右 min，不满足就按方向移动 i。贴边用正负无穷哨兵。奇数取左半最大，偶数取左 max 和右 min 的均值。O(log min(m,n))。"

二分题的通用面试心法：**先一句话说清"我在二分什么、合法条件是什么"，再动手**——二分 bug 九成出在"没想清楚不变量就开写"。lowerBound 是这一组的母题：插入位置、双边界、旋转数组收尾全能靠它表达。
