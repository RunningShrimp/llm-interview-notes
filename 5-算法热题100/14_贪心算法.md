# 14 | 贪心算法：每步都拿当下最优

> LeetCode 热题 100 · 贪心组全 3 题：LC121 / LC55 / LC45
> 目标：把"什么时候敢用贪心"想明白。

## 一、贪心 vs DP 判断表（开场必背）

| 判断维度 | 贪心 | DP |
|----------|------|-----|
| 一句话 | 每步拿局部最优，不回头 | 所有子状态都算一遍再取最优 |
| 依赖性质 | 贪心选择性质 + 最优子结构 | 最优子结构 + 重叠子问题 |
| 后效性 | 要求**无后效性**：这步选完，未来只依赖某个可合并的极值 | 允许复杂依赖，靠状态定义装下历史 |
| 实现形态 | 排序 / 一遍扫描，维护极值 | 状态数组 + 转移方程 |
| 复杂度 | 通常 O(n) 或 O(n log n) | 通常 O(n²)、O(n·k) |
| 典型翻车 | 局部最优拼不出全局（币值 1,3,4 凑 6：贪心 4+1+1 三枚，最优 3+3 两枚） | 状态漏转移 |

判断三连（自问）：

1. **排序/扫描一遍，每个元素只做一次决定，行不行？** 行 → 贪心候选。
2. **"当前最优"会不会坑了后面？** 说不清为什么不会 → 退回 DP。
3. **未来只取决于某个"可维护的极值/边界"吗？**（历史最低、最远可达、层边界）→ 是，贪心，这个极值就是你要维护的**唯一状态**。

本组三题全是"维护一个极值"：LC121 维护**历史最低价**，LC55 维护**最远可达**，LC45 维护**当前层边界**。

## 三、LC121 买卖股票的最佳时机（简单）

### 题干简述

`prices[i]` 是第 i 天股价，**只能某天买入、之后某天卖出**（一次交易），求最大利润，不能交易返回 0。`[7,1,5,3,6,4] → 5`。

### 解题思路（直觉引导）

暴力：双重循环枚举 (买, 卖) 对，O(n²)，pass。

反过来想：**站在第 i 天想卖出，最佳买入日是前 i-1 天里的最低价那天。** 一遍扫描维护两个东西：

1. `minPrice`：**历史最低价**（唯一要维护的状态）；
2. `profit`：`今天卖出的利润 = prices[i] − minPrice`，和历史最优打擂台。

```
i:      0    1    2    3    4    5
价格:   7    1    5    3    6    4
minP:   7    1    1    1    1    1   ← 历史最低一路下修
卖利润: -    -    4    2    5    3   ← max = 5 ✓
```

### 完整可编译代码

```go
package main

import "fmt"

func maxProfit(prices []int) int {
	if len(prices) == 0 {
		return 0
	}
	minPrice := prices[0] // 历史最低（贪心维护的唯一状态）
	profit := 0
	for i := 1; i < len(prices); i++ {
		if p := prices[i] - minPrice; p > profit { // 假设今天卖
			profit = p
		}
		if prices[i] < minPrice { // 顺手下修历史最低
			minPrice = prices[i]
		}
	}
	return profit
}

func main() {
	fmt.Println(maxProfit([]int{7, 1, 5, 3, 6, 4}) == 5) // true
	fmt.Println(maxProfit([]int{7, 6, 4, 3, 1}) == 0)    // true（一路跌，不交易）
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(n) |
| 空间 | O(1) |

### 易错点

1. `prices[0]` 取值前没判空数组。
2. 先更新 min 再算利润 vs 先算利润再更新 min：两种顺序本题都对（今天买今天卖利润 0 无害），但**要能说清为什么对**，面试会追问。
3. 只许一次交易，别写成 LC122（可多次交易，贪心叠加所有上涨段差值）。

### 🎤 口述模板

> "站在每天想：今天卖，最优买点就是之前的历史最低。一遍扫描维护 minPrice 和最大利润，O(n) O(1)。本质贪心：未来决策只依赖历史最低这一个极值，无后效性。"

## 四、LC55 跳跃游戏（中等）

### 题干简述

`nums[i]` 表示站在下标 i 最多能跳 `nums[i]` 步（可以少跳）。从下标 0 出发，**能否到达最后一个下标**？`[2,3,1,1,4] → true`；`[3,2,1,0,4] → false`。

### 解题思路（直觉引导）

从每个格子 BFS 枚举能到的地方？O(n²)，可以但丑。

换视角：**不用管"怎么跳"，只管"最远能摸到哪"。** 维护 `farthest` = 所有踩过的格子能延伸到的最远下标：

- 扫到 i 时若 `i > farthest`：i 根本到不了（前面所有覆盖都不含 i）→ false；
- 否则用 `i + nums[i]` 扩展 farthest；
- `farthest ≥ n−1` 提前收工。

```
[2,3,1,1,4]
i=0: farthest = 0+2 = 2        覆盖 [0..2]
i=1: farthest = max(2, 1+3)=4  覆盖 [0..4] ⊇ 终点 → true ✓

[3,2,1,0,4]
i=0..3: farthest 始终 = 3      覆盖只有 [0..3]
i=4: 4 > 3 → 到不了 → false ✓
```

为什么贪心对：farthest 单调不减，且每个可达格子都会被扫到——它就是"可达集合右边界"的精确刻画。

### 完整可编译代码

```go
package main

import "fmt"

func canJump(nums []int) bool {
	farthest := 0 // 能到达的最远下标（唯一贪心状态）
	for i := 0; i < len(nums); i++ {
		if i > farthest { // 连 i 都够不着，后面全废
			return false
		}
		if i+nums[i] > farthest {
			farthest = i + nums[i]
		}
		if farthest >= len(nums)-1 { // 已覆盖终点
			return true
		}
	}
	return true // 单元素数组等兜底
}

func main() {
	fmt.Println(canJump([]int{2, 3, 1, 1, 4}) == true)  // true
	fmt.Println(canJump([]int{3, 2, 1, 0, 4}) == false) // true
	fmt.Println(canJump([]int{0}) == true)              // true（起点即终点）
	fmt.Println(canJump([]int{0, 1}) == false)          // true（第一步卡死）
}
```

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(n) |
| 空间 | O(1) |

### 易错点

1. 判 `i > farthest` 必须放在**更新 farthest 之前**。
2. `farthest ≥ n−1` 提前返回，配合 break 写法时防数组越界类花活。
3. 别用"每步跳到能跳最远的格子"模拟——那是把 LC45 的思路错搬到判断题。

### 🎤 口述模板

> "我不模拟每步怎么跳，只维护 farthest：扫过的格子能延伸的最远位置。i 超出 farthest 就永远到不了返回 false；farthest 摸到终点就 true。O(n) O(1)，本质是覆盖区间单调右扩的贪心。"

## 五、LC45 跳跃游戏 II（中等）

### 题干简述

同 LC55 的跳跃规则，**保证能到达终点**，求到达最后一个下标的**最少跳跃次数**。`[2,3,1,1,4] → 2`（0→1→4）。

### 解题思路：隐性 BFS，"层"就是"步数"

把跳跃次数看成 BFS 的层数：

- 第 0 层（0 步可达）：{0}
- 第 1 层（1 步可达）：从第 0 层出发能到的下标集合
- 第 2 层：从第 1 层出发能到的……

同一层的可达集合是**一段连续区间**，所以 BFS 的队列能压缩成两个整数：当前层右边界 `curEnd` + 扫描中攒出的下一层最远点 `farthest`。

```
nums = [2,3,1,1,4]

第 0 层: [0]      从 0 出发最远到 0+2=2
第 1 层: [1,2]    1→1+3=4, 2→2+1=3，下一层最远 farthest=4
第 2 层: [3,4]    4 已是终点 → 答案 2 步 ✓

i:         0    1    2    3    4
i+nums[i]: 2    4    3    4    -
curEnd:    0 ─────→ 2 ─────→ 4   （i 触到 curEnd 时换层）
steps:        1         2
```

**"步数 +1 的时机"是本题灵魂**：当 i 走到当前层右边界 `curEnd` 时（`i == curEnd`），说明这一步的射程用尽——不管刚才从哪跳的，都必须**再起跳一次**：

1. `steps++`；
2. 新层右边界接力：`curEnd = farthest`。

两个细节：

- 循环条件 `i < n−1`：**终点不用再起跳**，扫到 n−1 就该收答案；
- `i == curEnd` 时必有 `farthest > curEnd`（题目保证可达），不会死循环。

### 完整可编译代码

```go
package main

import "fmt"

func jump(nums []int) int {
	n := len(nums)
	steps := 0    // 已跳步数 = BFS 层数
	curEnd := 0   // 当前层右边界
	farthest := 0 // 扫描中攒出的下一层最远点
	for i := 0; i < n-1; i++ { // 终点下标不用扫
		if i+nums[i] > farthest {
			farthest = i + nums[i]
		}
		if i == curEnd { // 本层射程用尽 → 必须再跳一步
			steps++           // 步数 +1 的唯一时机
			curEnd = farthest // 边界接力
		}
	}
	return steps
}

func main() {
	fmt.Println(jump([]int{2, 3, 1, 1, 4}) == 2) // true
	fmt.Println(jump([]int{2, 3, 0, 1, 4}) == 2) // true
	fmt.Println(jump([]int{1}) == 0)             // true（已在终点）
	fmt.Println(jump([]int{1, 2}) == 1)          // true
}
```

走一遍 `[2,3,0,1,4]`：

```
i=0: farthest=2, i==curEnd(0) → steps=1, curEnd=2
i=1: farthest=max(2, 1+3)=4
i=2: farthest 仍 4, i==curEnd(2) → steps=2, curEnd=4
i=3: farthest=4（i=4 即 n-1 不进循环）→ 返回 2 ✓
```

### 三种视角对比（能讲出来就是加分）

| 视角 | 怎么理解 steps+1 | 复杂度 |
|------|------------------|--------|
| 隐性 BFS | 层与层的"换层"时刻，新层边界=旧层内攒出的 farthest | O(n) |
| 贪心边界 | 每步选"下一步覆盖最远"的位置，边界到达即结算 | O(n) |
| 显性 BFS | 队列存下标 + visited 去重逐层扩展 | O(n) 但常数大代码长 |

### 复杂度

| 项 | 复杂度 |
|----|--------|
| 时间 | O(n) |
| 空间 | O(1) |

### 易错点

1. **循环写 `i < n` 而非 `i < n-1`**：会在终点上多结算一次，`[1]` 返回 1（正确是 0）。
2. `steps++` 判断写成 `i >= curEnd` 且忘了先更新 farthest——接力棒丢失，`[2,3,0,1,4]` 翻车。
3. 题目保证可达才这么做；不保证可达（LC55）要先判 `farthest <= i` 死局。两题连考时别说混。

### 🎤 口述模板

> "最少跳跃次数 = BFS 层数，每层是一段连续区间，所以用 curEnd 记当前层右边界、farthest 攒下一层最远点：i 一碰到 curEnd 就说明本层射程用尽，steps 加一并把 curEnd 接力成 farthest。循环只扫到 n−2，终点不用再起跳。O(n) O(1)。"

贪心题的通用面试姿势：**先说清"我维护的极值为什么无后效性"，再写代码**——这句话说出口，面试官就知道你不是背题。
