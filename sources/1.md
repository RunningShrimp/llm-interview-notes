### AI 工程化全栈专家面试大纲
#### 第一阶段：后端工程基础（你的基本盘，需展现深度与高并发经验）
*这不仅是为了回答基础题，更是为了在后续AI场景中自然映射。*
1.  **高并发与分布式架构**
    *   **核心机制**：进程/线程/协程模型（结合语言特性，如Go的GMP或Python的Asyncio）、I/O多路复用。
    *   **微服务治理**：服务注册发现、限流熔断、降级策略、链路追踪。
    *   **消息队列**：Kafka/RabbitMQ 在解耦、削峰、异步通知中的深度应用。
2.  **数据存储与性能调优**
    *   **关系型数据库**：MySQL 索引原理（B+树）、慢查询优化、分库分表策略、事务隔离级别与锁机制。
    *   **缓存系统**：Redis 数据结构选型、缓存雪崩/击穿/穿透的工程解决方案、分布式锁的实现。
3.  **系统设计与韧性**
    *   如何设计一个高可用的接口（SLA定义、容量评估）。
    *   幂等性设计、分布式事务（Saga、TCC等概念理解）。
#### 第二阶段：AI 工程化基石与大模型基础（后端向AI的平滑过渡）
*不需要懂怎么训练模型，但需要懂怎么调用和管控模型。*
1.  **LLM API 工程化对接**
    *   鉴权机制与长连接管理。
    *   **流式响应处理**：SSE（Server-Sent Events）机制、Web端与移动端的流式数据接收与渲染。
2.  **Prompt 工程化**
    *   System Prompt 与 User Prompt 的隔离设计。
    *   Few-Shot 提示词的动态构建。
    *   **后端视角的难点**：Prompt 模板管理、变量注入防注入攻击。
3.  **AI 网关与基础设施**
    *   **多模型路由与降级**：如何设计一个网关，支持在 OpenAI、Claude、GLM 等模型间动态路由、故障转移和成本控制。
    *   **Token 管理与计费**：预估 Token 消耗、截断策略、基于用户配额的 Redis 计数器设计。
#### 第三阶段：知识库构建与 RAG 工程（企业级AI应用的核心）
*这是面试重灾区，重点考察如何解决“幻觉”和“检索不到”的问题。*
1.  **非结构化数据处理**
    *   文档解析：PDF/Word/Excel 的解析难点（表格、图片、多栏排版），OCR 与版面分析的结合。
    *   **切块策略**：固定长度切块、按结构切块（Markdown层级）、语义切块的工程实现。
2.  **Embedding 与向量数据库**
    *   向量化模型选型（如 BGE、OpenAI Embedding）。
    *   **向量数据库选型与应用**：Milvus、Qdrant、PgVector 的对比与选型依据。
    *   **索引机制**：HNSW、IVF 的概念（懂原理和参数调优即可，不需懂数学推导），空间与时间的权衡。
3.  **RAG 链路进阶**
    *   **Naive RAG** -> **Advanced RAG** 的演进。
    *   **检索前优化**：查询重写、HyDE（假设性文档嵌入）、多路召回。
    *   **检索后处理**：重排模型（Reranker，如 BGE-Reranker）的作用与工程部署、上下文压缩。
    *   **工程难点**：如何处理海量文档的增量更新？如何设计异步的向量化入库流水线？
#### 第四阶段：Agent 构建与编排（从被动回答到主动执行）
*考察系统设计能力和对外部工具的封装能力。*
1.  **Agent 核心架构**
    *   ReAct 模式与 Plan-and-Execute 模式的区别与适用场景。
    *   循环控制：Agent 何时停止？最大轮次限制与超时控制。
2.  **工具调用**
    *   Function Calling / Tool Use 的协议规范。
    *   **后端视角的难点**：如何将现有的 RESTful API 封装为 LLM 可理解的 Tool Schema？如何处理 Tool 执行异常并反馈给 LLM 让其重试？
3.  **Agent 框架与编排**
    *   LangChain / LlamaIndex 的核心设计思想及优缺点（避免过度依赖框架，强调原理解析）。
    *   **工作流编排**：基于 DAG（有向无环图）的复杂任务编排，状态机设计，多 Agent 协作。
    *   **记忆机制**：短期记忆（对话历史截断、Sliding Window）与长期记忆（基于向量库的 Memory 检索）。
#### 第五阶段：评测、可观测性与生产化部署（体现资深度）
*AI应用最大的挑战是“不可控”，这一块能体现你六年经验带来的严谨性。*
1.  **LLM 评测体系**
    *   RAG 评测指标体系（RAGAS或TruLens）：Faithfulness（忠诚度）、Answer Relevance（答案相关性）、Context Precision/Recall（上下文精确率/召回率）。
    *   Agent 评测：工具选择的准确性、执行路径的合理性、最终任务完成率。
    *   **自动化评测流水线**：如何用 LLM-as-a-Judge 构建自动化回归测试集。
2.  **可观测性与监控**
    *   链路追踪的改造：在传统Trace中注入 LLM 的 Input/Output、Token 消耗、Prompt 模板版本。
    *   质量监控：线上输出质量的实时采样监控，敏感词与安全合规拦截机制。
3.  **部署与性能优化**
    *   推理加速：vLLM 等推理框架的概念（不需深入，知道能提升吞吐量即可）。
    *   高并发场景下的队列设计：LLM 推理是计算密集型+长耗时任务，如何设计请求队列、优先级调度和超时丢弃机制。
#### 第六阶段：扩展与前沿工程（加分项）
1.  **MCP (Model Context Protocol)**：2024-2025年兴起的标准协议，如何通过MCP实现即插即用的工具生态。
2.  **数据隐私与安全**：PII（个人身份信息）脱敏、Prompt 注入攻击防护、输出内容安全过滤。
